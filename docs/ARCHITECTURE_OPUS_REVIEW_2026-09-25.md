# 모델 구조 개선안: Opus와의 비교 검토

## 범위와 실행 근거

사용자가 요청한 구조 토의를 위해 Claude Code 2.1.281에서 `--model claude-opus-5-5 --effort high`로 두 차례 검토를 실행했다. 두 응답 모두 실제 `modelUsage`가 `claude-opus-5-5`이고 오류 없이 종료됐다. 응답 기록의 소요 시간은 각각 63,508ms, 57,929ms다. 도구와 MCP 접근을 제한하고 필요한 코드 발췌·기록만 제공했다. 두 번째 요청에는 첫 응답에 대한 Codex의 반론과 추가로 확인한 과거 실험을 포함했다.

이번 작업은 설계 검토다. 학습·새 음원 생성·특징 추출·GPU 기동·제출은 수행하지 않았다. 두 모델의 합의는 성능 검증이 아니다. 원문·요청·실행 영수증은 원본 작업공간의 Git 제외 경로 `_workspace/claude_opus55_review_20260924/`에 보존했다.

## 확인한 기준 구조

- HTDemucs로 보컬·반주를 분리한다. 특징 추출기는 동결한다.
- 음악: MERT L12의 1024차원 구간 특징 → 표준화 → 1024→128→1 MLP → log-mean-exp. 기존 WindowMIL도 구간별 판별을 수행하며, 헤드의 집계는 순서에 무관하다.
- 음성: DF-Arena의 1280차원 보컬 특징 → Linear(1280, 2) → max 집계.
- 각 경로에서 seed 41·42·43의 확률을 평균한다.
- PANNs·stem 통계 기반 presence와 검증 자료로 적합한 CDF 결합기를 사용한다.
- 현재 캐시는 약 4.04초 구간의 특징이다. 음악 hop은 약 2.02초이며 마지막 구간 간격은 다를 수 있다. 원본 음원 인코더 특징과 정렬된 구간별 가창·에너지 특징은 이 캐시에 없다.

근거: [WindowMIL](../repository/localization_models.py), [캐시 생성·검증](../repository/full_bank_features.py), [분류기 평가](../repository/full_bank_evaluate.py), [결합기](../repository/decision_heads.py). DataV4 보존물과 사용자 제공 최고점 제출 ZIP의 정확한 일치는 여전히 미확인이다.

## 토의로 수정한 판단

| 쟁점 | 검토 후 판단 |
|---|---|
| 음악 시간축 CNN을 우선 적용 | 비교 후보로 유지한다. 음악 관련 오류가 많다는 사실만으로 시간 문맥 부족을 원인으로 확정할 수 없다. 구간별 보정 대조군이 필요하다. |
| 1280→128→1 가창 보정 MLP | 조건부 후보로 내린다. 가창 내부의 순위 판별 문제와 도메인 간 점수 이동을 먼저 구분하고, 같은 선형 헤드 재학습과 비교한다. |
| zero-init으로 기존 성능 보호 | 초기 출력 재현만 보장하는 설계다. 학습 후 퇴행과 데이터 편향은 별도 평가해야 한다. |
| 기존 CNN 재사용 | 구현 일부를 재사용할 수 있다. 현재 완성 모듈은 파일 점수를 내므로 구간별 보정 경로로 연결하는 작업은 필요하다. |
| raw+stem·다층 MERT | 후순위 표현 비교로 남긴다. 새 특징 추출이 필요하며 기존 캐시로 끝난다고 표현하지 않는다. |

Opus의 지적도 그대로 채택하지 않았다.

1. 첫 응답은 기준 FILE 결합을 단순 max처럼 다뤘다. 실제 CDF 결합기를 제시하자 이를 정정했다. 고정 결합기에서의 FILE 결과와 각 성분 지표를 모두 보고, 별도 calibration 재적합 결과는 구분한다.
2. 선형·MLP 후보의 실패만으로 표현 실패를 증명할 수 없으며, 비선형 헤드가 분리 잔여물 문제를 해결할 수 없다는 단정도 철회했다. 라벨·표본·학습 조건을 함께 점검해야 한다.
3. 구간별 저에너지 마스킹은 현재 캐시만으로 가능한 실험이 아니다. 첫 비교에서 제외한다. 낮은 에너지 자체를 무효 구간으로 간주하지 않는다.
4. seed 변동만을 채택 임계로 쓰지 않는다. 같은 파일의 paired 비교, 공유 부모를 고려한 component 단위 불확실성, seed별 결과를 구분한다.
5. 2차 응답의 `prev` 혼입 우려는 저장된 실제 설정에서 적용되지 않았다. 원본 작업공간의 `results/data_v4_20260923/data_v4_phase_c_20260923T1653Z/train_duration_balanced/file_ensemble.json`은 `max=1`, `noisy_or=1`, `max_nopresence=1`이며 `prev` 항목이 없다. 해당 파일 SHA-256은 `3e0056d110d8b1ea6b5a11c60da3747de322bfc1f8bacf415b8bc4adec0af6a4`다. 설정 확인이 과거 학습 노출 문제 전체를 해소하는 것은 아니다.
6. 마지막 유효 구간을 단순히 버리라는 제안은 채택하지 않는다. 실제 시작 시각·길이를 보존하고, padding과 불규칙한 구간 간격을 구분한다.

## 과거 CNN 결과의 의미

[단순화 보고서](../repository/results/temporal_h100_simple_20260915/Temporal_H100_Simplification_Report.ipynb)는 6층 CNN Music EER 0.4333, 2층 0.3731, 선형 0.3667을 기록했다. CNN은 3개 seed 평균이고 선형은 seed 41 하나다. [후속 compact 보고서](../repository/results/temporal_h100_compact_20260915/Temporal_H100_Compact_Tuning_Report.ipynb)는 64채널·3층의 튜닝 전 0.2889, 튜닝 선택 C08의 0.2954를 기록했다.

이는 과거 768차원 특징과 재사용 평가 자료 190개 중 음악 대상 150개의 결과다. 현재 DataV4나 새 residual 경로의 성능이 아니며, CNN의 일괄 성공·실패를 뜻하지 않는다. 튜닝 지표의 개선이 평가 지표로 옮겨가지 않은 사례이므로, 개발용 선택과 최종 평가를 분리한다.

## 최소 실험 순서

### 1. 기준 재현과 오류 진단

기준의 3개 seed, presence, CDF 결합을 복원해 같은 ID·마스크에서 비교한다. 기존에 수행한 756행 CPU 진단은 학습 노출을 배제하지 못하므로 독립 평가로 재사용하지 않는다. 발화·가창·혼합 음원 내부의 판별력과 전체 점수 분포를 구분한다. 실제 결합기에서 성분 교체를 진단할 경우 바꾼 변수를 명시하고, 가상 정답 대입 결과를 달성 가능한 개선 폭으로 해석하지 않는다.

### 2. 음악 구조만 비교

같은 데이터에서 다음 세 후보를 비교한다.

1. 보존 모델 그대로.
2. 기존 음악 헤드 + 구간별 residual 보정: kernel=1.
3. 기존 음악 헤드 + 시간축 residual 보정: kernel=3.

두 학습 후보는 채널·층수·학습 step·seed·마스크를 맞추고 커널에 따른 파라미터 차이는 기록한다. 이는 시간 문맥의 고유한 인과 효과를 완벽히 분리한 실험은 아니다. 검증 목적은 시간축 후보가 더 단순한 후보보다 실용적 이득이 있는지 확인하는 것이다. 최종 보정 투영만 0으로 초기화하고 동시에 다른 곱셈 gate까지 0으로 만들어 gradient를 끊지 않는다. 기존 head·backbone·presence·결합기는 고정한다.

둘 다 이득이 없으면 라벨·데이터·학습 조건을 재점검한다. 효과가 비슷하면 kernel=1을 우선한다. 시간축 후보는 원천별·seed별 결과와 paired 불확실성을 포함해 추가 이득이 뒷받침될 때만 채택한다. 데이터 추가와 이 구조 변경을 같은 비교에 섞지 않는다.

### 3. 음성 조건부 비교와 최종 평가

기존 데이터로 선형 헤드를 추가 학습한 대조군과, 균형을 보강한 데이터로 같은 step만큼 학습한 후보를 비교한다. 가창 내부의 순위 판별 문제가 남을 때만 동일 데이터에서 residual MLP의 추가 이득을 확인한다. 도메인 보정은 별도 후보로, upstream 학습과 겹치지 않은 calibration 자료에 적합한다.

개발용 자료로 선택을 끝낸 뒤 최종 holdout을 한 번 평가한다. 이전 가중치의 학습 노출까지 확인되지 않은 출처를 미관측 원천이라고 부르지 않는다. 원본+분리 특징이나 다층 MERT는 앞 단계 결과를 보고 하나씩 검토한다. 추가 데이터 파일럿 준비는 병행할 수 있다.

## 이번 검증의 한계

확인한 것은 실제 Opus 모델 응답, 요청 설정·내용 해시, 코드 구조, 과거 보고서 수치, 저장된 결합 설정이다. 새 구조의 학습 연결성·예측 일치·일반화·Mac 처리량은 실행하지 않았다. 후속 구현에서 초기 출력 재현과 의도한 파라미터의 gradient를 확인하고, 품질은 실제 예측과 독립적인 평가 자료로 판단해야 한다. 문서만 변경했으므로 모델 테스트를 실행하지 않았다.
