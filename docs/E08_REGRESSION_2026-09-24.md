# E08 성능 하락 진단

사용자는 ADS 점수를 묻는 질문에 이전 제출 `0.7683174603`, 현재 제출 `0.7064761905`라고 답했다. 차이는 `-0.0618412698`로 약 6.18%p 하락이다. 사용자 제공 수치이며 사이트에서 직접 조회하지 않았다. 이전 제출 이름은 아직 확인하지 못했다. 이번 조사는 보존된 DataV4 가중치와 E08을 같은 캐시에서 CPU로 비교한 결과다. DataV4가 사용자가 비교한 제출이라고 단정하지 않는다.

## 확인한 문제

E08의 기존 비교 대상 E00은 과거 제출 모델이 아니라 같은 부분 데이터로 새로 학습한 기준선이다. E00보다 개선됐다는 결과는 과거 제출보다 개선됐다는 근거가 되지 않는다. 제출 후보 선정 전에 과거 제출과 같은 데이터에서 비교하지 않은 것이 검증 누락이다.

E08은 기존 음악 헤드를 이어 학습하지 않았다. 음악은 새 WindowMIL을 초기화하고 부분 데이터 373개로 학습했다. 음성도 과거 학습 완료 헤드 대신 DF-Arena 초기 분류기에서 시작했다. 전체 train 5,196개 중 음성 라벨은 fake 4,325개·real 676개이며, 학습 코드는 클래스·출처별 loss 가중치를 적용한다. 따라서 단순 클래스 개수만으로 하락 원인을 확정하지 않는다. 데이터는 추출 순서의 앞부분이고 음악 selection은 35개뿐이다.

DataV4와 비교하면 seed 3개에서 1개로 감소했고, duration balancing을 사용하지 않았으며, 학습된 presence 보정기와 FILE 결합기를 기존 max 방식으로 바꿨다. 상위 30% 음성 집계 하나만 달라진 실험이 아니다.

## CPU 비교

보존 캐시의 selection 421개와 calibration 335개, 총 756개를 사용했다. 학습은 하지 않았다. 실제 이전 checkpoint의 해시, encoder·전처리와 현재 캐시의 호환성, 각 캐시 파일의 ID·해시를 확인했다. 기존 학습·평가 함수를 재사용해 CPU에서 실행했다. [재현 코드](evidence/lb_e08_regression_20260924/compare.py) · [전체 지표](evidence/lb_e08_regression_20260924/comparison.json)

| calibration 비교 | File EER | Voice EER | Music EER |
|---|---:|---:|---:|
| 보존 DataV4 원래 구성 | 0.055970 | 0.023566 | 0.093074 |
| DataV4 헤드 + 기존 max 결합 | 0.061567 | 0.023566 | 0.093074 |
| E08 제출 구성 | 0.089552 | 0.061008 | 0.186147 |
| E08 + DataV4 음악 헤드 + max | 0.072761 | 0.061008 | 0.093074 |
| E08 + DataV4 음성 헤드 + max | 0.089552 | 0.023566 | 0.186147 |

각 EER 분모는 File 335개, Voice 308개, Music 43개다. calibration은 현재 E08 학습·epoch 선택에는 사용하지 않았지만 **과거 DataV4 학습·보정 데이터와의 중복은 배제하지 않았다.** 추출 순서에 따른 부분 데이터이므로 독립 일반화 성능을 입증하지 않는다. 이번 분석으로 calibration도 진단에 노출됐다. 정답 누락으로 모든 구성의 종합 score는 null이다.

selection에서도 DataV4 원래 구성의 File/Voice/Music EER은 0.054321/0.037621/0.114379, E08은 0.062746/0.050161/0.171569였다. 확인한 두 부분 집합에서 E08은 기존 DataV4보다 열세다. 기존 음악 헤드로 되돌렸을 때 calibration File EER도 낮아졌지만, 이것만으로 리더보드 회복을 보장할 수는 없다.

## 다음 판단 기준

E08을 개선된 기본 모델로 취급하지 않는다. 사용자가 비교한 실제 이전 제출을 먼저 특정하고, 그 모델을 기준으로 음악·음성·결합기를 한 번에 하나씩 바꿔 비교한다. 평가 데이터와 과거 학습 데이터의 출처 중복을 먼저 확인한다. 일부 캐시만 사용해야 한다면 출처·클래스·음악/음성 구성이 치우치지 않도록 선정하고, 기존 가중치 유지와 재학습을 분리한다.

ADS는 File 50%, Voice 20%, Music 30% 비중이므로 음성 지표만으로 후보를 선택하지 않는다. [공식 평가 산식](https://dacon.io/competitions/official/236749/overview/evaluation). 이번 작업에서 새 GPU 실행·제출 ZIP 변경·대회 제출은 하지 않았다.
