# Opus 5.5 xhigh 후속 개선 토론

작성일: 2026-09-25. 이 문서는 확정된 PANNs v1의 후속 개선 후보를 정리한 연구 메모다. 사용자가 여러 실험을 진행해도 된다고 명시했으므로, 미시도라는 이유로 후보를 줄이지 않고 아래 비교군을 준비한다. v1의 구조·손실·역할·채택 기준은 바꾸지 않는다. 이번 토론으로 새 데이터 수집·생성·GPU 학습을 실행하거나 성능 개선을 확인한 것은 아니다.

## 실제 호출과 검토 범위

Claude Code 2.1.281에서 `--model claude-opus-5-5 --effort xhigh`를 지정했다. 세 번의 독립 print 호출로 먼저 제안을 비판하게 한 뒤, 실제 회귀 근거·반박을 제공하고 여러 실험을 적극 비교하라는 사용자 추가 지시까지 논의했다. 각 호출은 720초 제한으로 실행했고 세 응답 metadata에서 `claude-opus-5-5`를 확인했다. 첫 호출은 193.95초, 두 번째는 155.15초, 세 번째는 118.56초에 종료 코드 0으로 완료됐다. 세 init 응답 모두 `tools=[]`, `mcp_servers=[]`였다. xhigh는 실제 CLI 인자로 지정해 수락됐으며 모델 내부의 연산 배분을 별도로 검증한 것은 아니다. `--safe-mode --restricted --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --disable-slash-commands --no-session-persistence --no-chrome`로 도구·MCP·사용자 hook·프로젝트 자동 문맥을 끄고 제공한 자료만 논의했다. Claude에 음원·가중치·인증정보는 제공하지 않았다.

모델의 동의만으로 품질을 검증할 수는 없다. 이전 Opus high 검토는 과거 초안에 관한 것이고, 이번 xhigh 토론은 후속 제안과 평가 방법을 검토한 것이다. 현재 코드가 설계대로 작동한다는 판정은 별도 실행 증거로 확인한다.

## 토론 전에 제안한 방향

코드 수정과 별개로 다섯 방향을 먼저 제시했다. 실제 최고점 제출물의 정체성 확인, 미사용 원천 평가자료 확보, FILE을 바꾸는 presence 오류 분석, SNR·시간 점유율·codec 대응 실험, 그리고 오류 근거에 따라 고르는 보정·pooling 후속 비교다. 대량 수집이나 새 backbone을 우선하지 않고, 현재 자료의 누락 라벨·출처 편향·혼합음 부족부터 확인하자는 안이다.

## 토론에서 바로잡은 주장

E08은 PANNs만 바꾼 실험이 아니었다. 음악·음성 fake head, seed 수, duration balancing, presence와 FILE 결합 방식이 함께 달라졌다. Opus가 첫 답변에서 제시한 “fake head가 같다면 ADS 하락은 FILE 하락”이라는 조건부 산술을 실제 회귀 원인으로 채택하지 않았다. 근거를 추가한 뒤 다시 논의했고, Opus는 실제 비교에 대한 FILE만의 하락 추정·회복 가능 폭·보정 원인 추정을 철회했다. [E08 회귀 기록](../../E08_REGRESSION_2026-09-24.md).

정답 presence를 대입했을 때 뒤집히는 오류 수로 달성 가능한 G의 상한을 계산할 수도 없다. EER 임계값과 다른 파일의 순위가 함께 바뀌고, hard presence 대입은 실제 학습 모델과 다르기 때문이다. 이는 민감도 진단으로만 남긴다.

현재 v1의 selection 후보 기준은 seed 평균 G>0, 두 presence AUC의 평균 차이≥0이다. 최종 독립 평가에서는 실제 배포 seed 41의 G 차이 95% 하한>0, 두 AUC 차이 하한≥0을 요구한다. 이미 AUC가 높은 상황에서는 최종 기준이 보수적이어서 판단 유보가 많을 수 있다. 그 사실을 미리 알리되 이번 작업에서 허용 퇴행 폭을 만들거나 기준을 완화하지 않는다. 미래 정책 변경이 필요하면 결과를 보기 전에 별도 버전으로 정한다. [확정 기준](../specs/2026-09-25-panns-cnn-expanded-design.md).

`development`는 오류 분석, `selection`은 사전에 정한 후보 비교 역할이다. 둘 다 과거 모델에 노출된 자료를 포함하므로 독립 평가라고 부르지 않는다. 이름을 바꿔 holdout으로 재사용하지 않는다. 모델 불일치로 모은 자료는 편향을 명시한 진단 패널 또는 train 후보로 사용하고, 무작위로 고른 봉인 평가 패널과 섞지 않는다.

## 검토 과정에서 채택하지 않은 의견

- **ΔAUC로 ΔFILE을 예상하는 곡선:** 같은 AUC에서도 틀린 파일·확률 크기·fake head와의 조합이 다를 수 있다. 둘을 함께 기록할 수는 있지만 하나로 다른 하나를 예측하거나 원인을 확정하지 않는다.
- **보정 후 차이의 CI가 0을 포함하면 표현 개선이 아니라는 결론:** 개선 증거가 부족하다는 뜻이며 두 방법의 동등성이나 보정 원인의 증명이 아니다. 보정 전후의 대응 비교를 진단으로만 쓴다.
- **시간별 점수 평균=파일 logit이라는 간편한 진단:** 현재 경로에는 527 sigmoid, class max, file max/mean/q90, 표준화·logistic이 있어 이 선형 등식의 전제가 맞지 않는다. 실제 기존 readout을 그대로 계산한다.
- **정답 방향으로 presence를 크게 옮긴 결과의 임의 k/m 기준으로 후속 전체를 중단:** 합성 민감도 값은 학습 가능한 변화량이 아니다. 진단의 측정량·판정 조건은 미리 정하되, 임의 수치 하나를 일반화 근거나 달성 가능한 개선 상한으로 쓰지 않는다.
- **selection에서 최종 독립 평가의 CI 통과를 요구하는 표현:** 개발 후보 선정과 최종 채택은 위 확정 기준대로 구분한다. selection 결과만으로 배포 채택하지 않는다.

3차에서 Opus는 위 인과 해석과 역할 혼동을 철회했고 여러 실험군을 병행하는 방향을 제안했다. 다만 새 답변의 `development`에서 head 적합, 균등 attention이면 탈락, source만으로 label이 예측되면 자료 전체 탈락 같은 규칙도 그대로 채택하지 않았다. 학습은 train, 보정은 calibration에서만 수행한다. attention 집중도·source 편향은 실제 동작과 원천 밖 결과를 함께 해석할 진단값이다. SE의 첫 step에서 일부 gradient가 0일 수 있다는 확정 설계도 유지한다.

## 여러 후보를 비교하는 실험 구성

확정 v1을 공통 대조군으로 보존하고 후속 비교는 v2 또는 별도 fake 분기 실험으로 구분한다. 아직 시도하지 않았다는 이유로 제외하지 않는다. Mac의 작은 실제 실행으로 잘못된 라벨·끊긴 gradient·메모리 초과·입력 불일치를 먼저 걸러내고, 의미 있는 관측이 가능한 후보 여러 개를 A100에서 비교한다. 작은 패널의 점수가 좋다는 이유만으로 최종 후보를 채택하지 않는다.

모든 arm의 label·데이터 역할·optimizer step·초기 가중치·실행 자원·종료 조건을 결과 전에 고정한다. gradient 단절, 비유한 값, 계보 충돌, 라벨 부적격, 정한 메모리 초과는 즉시 중단할 이유다. 단순히 미실험이라는 이유는 중단 기준이 아니다. 실제 A100 처리량을 측정한 뒤 여러 arm의 예산을 산정하며 임의의 기존 시간 제한을 그대로 적용하지 않는다. 이 문서는 새 유료 자원 기동이나 무제한 실행의 승인을 뜻하지 않는다.

독립 평가자료 설계·권리 확인·계보 검사는 병행한다. complete label이 없어 FILE EER·G를 계산할 수 없는 자료는 presence 진단으로만 쓴다. 탐색 결과로 후보를 고정한 다음 별도 미사용 확인 자료에서 한 번 평가한다. 확인 자료를 본 뒤 후보를 다시 고르면 그 자료는 후속 독립 평가에서 제외한다.

## 토론과 별도로 실행한 CPU 진단

실제 score 진단도 진행했다. 이전 DataV4 후보의 11,371행과 그 후보에 맞는 CDF로 FILE 값을 다시 계산했으며 최대 절대 오차는 `5.55e-17`이었다. 이 기록만으로 현재 보존 패키지나 최고점 제출물과의 동일성을 입증할 수 없어 v1 결과나 최고점 제출물 재현으로 부르지 않는다. 과거 validation에 CDF를 적합한 이력이 있어 현재 역할명이 selection이어도 미노출 평가가 아니다.

presence 정답이 알려진 같은 6,268행·2,572개 parent component의 baseline FILE EER은 `0.10289136`이었다. 음성 presence 정답 대입의 EER 차이는 0, 음악 정답 대입은 `−0.00365574`였고 paired bootstrap 95% 구간은 `[−0.00635765, +0.00012922]`로 0을 포함했다. 사전에 정한 presence temperature 0.5와 2의 EER 차이는 각각 `−0.00046531`이었으며 presence AUC는 수치상 같았고 두 구간 모두 0을 포함했다. 음성·음악이 둘 다 없는 표본은 이 패널에 **0개**였다.

이 결과로 PANNs의 개선 상한이나 리더보드 회복 폭을 계산하지 않는다. 기존 패널에서 단순한 presence 크기 변경의 이득이 불확실하며 잡음·둘 다 없음 조건이 빠져 있다는 사실이 다음 실험의 근거다. 짧은 성분·약한 음악·비음성 hard negative를 보완하고 별도 fake 분기 실험도 함께 검토한다. 자세한 입력 해시·분모·노출 내역은 [CPU 진단 기록](2026-09-25-cpu-score-diagnostics.md)에 남긴다.

## 데이터와 생성 자료

이미 확보한 D+ 1,477개를 신규 데이터처럼 다시 수집하지 않는다. 확정 D0는 그대로 보존한다. 후속 데이터 비교는 고정 R1을 대조군으로 미리 등록해 v2-DATA에서 병행할 수 있으며, v1 후보와의 상호작용은 별도 arm으로 비교한다. 같은 optimizer step의 D0 대 D+ 비교로 편입 효과를 확인하고 v1 실행 중 D0를 교체하지 않는다. class weight는 1을 유지하며 알려진 라벨 비율·원천 구성·노출 파일 수를 함께 기록한다.

새 원천은 보완할 오류 유형과 비교 목적을 정해 추가한다. ESC-50과 BabySlakh는 소형 진단 후보이며, 전자는 환경음이라는 이유만으로 presence를 모두 0으로 두면 안 되고 후자는 현대 생성 AI 음악의 FAKE 정답으로 쓰면 안 된다. 실제 보컬·반주 대응쌍은 MoisesDB·MUSDB·MedleyDB에서 검토할 수 있지만 권리와 접근 조건을 먼저 확인한다. FSD50K는 대회 사용 연락 조건 때문에 보류한다. 이용조건·용량·출처는 [별도 1차 자료 조사](2026-09-25-data-method-evidence.md)에 정리했다.

MUSDB는 HTDemucs의 알려진 학습 자료다. 새로 내려받았다는 이유로 시스템 전체에 미노출된 평가라고 주장하지 않는다. 확인 가능한 과거 train·calibration·selection뿐 아니라 encoder·separator의 알려진 사전학습 원천과도 대조하고, 확인할 수 없는 upstream 노출은 한계로 남긴다.

AI를 쓰는 방법은 후보 라벨 검토, 작은 통제 합성, 생성 모델 비교로 나눈다. 허용된 부모 음원에 같은 처리 경로를 적용하면서 SNR·점유 시간·codec만 바꾸고, 두 부모의 계보를 모두 같은 역할에 묶는다. 생성 모델도 실험 후보로 두되 기존 승인 가중치부터 재사용하고, 생성 파일·모델 revision·prompt·seed·처리값을 보존한다. 생성된다는 사실이나 teacher 동의만으로 라벨을 확정하지 않는다. 소리가 거의 들리지 않거나 생성에 실패한 사례는 제외·미확정 처리한다.

## 방법론의 범위

linear-softmax와 auto-pool은 검토할 만한 MIL 대안이지만 논문의 사건 확률 집계와 현재 R5의 block6 특징 집계는 다르다. 짧거나 약한 성분이 segment/tag 수준에서는 잡히는데 파일 집계에서 사라지는지부터 확인한다. 같은 표현을 고정한 readout 비교를 v2로 설계하고 진단과 비교 결과를 함께 해석한다. 현재 cache를 그대로 쓸 수 있다고 가정하면서 segmentation까지 바꾸지 않는다. [MIL pooling 비교](https://arxiv.org/abs/1810.09050), [auto-pool](https://arxiv.org/abs/1804.10070).

양의 단조 보정은 단일 presence 점수의 순위를 바꾸지 않지만 FILE 결합을 바꿀 수 있다. 따라서 순위 개선과 보정 개선을 따로 보고하고, R0와 후보에 같은 제한된 보정 절차를 적용한다. 보정은 지정한 calibration 역할에서만 적합하며 현재처럼 노출된 자료의 결과는 진단으로만 해석한다. CDF 재적합을 v1의 필수 절차로 추가하지 않는다. [보정 원 논문](https://proceedings.mlr.press/v70/guo17a.html).

Mac M5 Pro 24 GB에는 자료·권리·계보 정리, CPU 디코딩·중복 탐지, 청취 큐, 작은 혼합, cached score 분석과 bootstrap을 맡긴다. 전체 메모리 상한 18 GiB를 유지하며 생성 모델을 병렬로 띄우지 않는다. A100은 남은 특징 추출과 확정 v1 학습에 우선 배정한다. 새 자료의 stem도 기준 경로에서 검증해야 하며, 짧은 MPS 속도 측정만으로 전량 처리 시간이나 CPU와의 동등성을 보장하지 않는다.
