| G5 seed 안정 | seed 3개 중 2개 이상이 G1 방향과 같음 | A/B |
| G6 잠근 평가 | 최종 후보 1개만: 현 최고 패키지 대비 ADS Δ ≥ −0.002 (비열등), 그리고 G3 층 악화 ≤ 0.015 | C (한 번) |

| G8 출처 | 새 데이터는 identified → accessible → downloaded → license/rule checked → quality audited → overlap audited → admitted를 모두 통과 | — |
- 한 클래스뿐인 층에는 EER/AUC를 계산하지 않는다. old val에서 정한 문턱(TPR 95 %)의 FPR 또는 FNR만 보고한다.
- 집계 개선이 핵심 층의 G3 위반을 가리면 탈락이다. 표본이 모자란 층(클래스별 독립 그룹 < 20)은 "판정 불가"로 보고하고
  그 층을 근거로 채택하지 않는다.
- 이 기준은 LB 개선을 보장하지 않는다. LB 점수, 개발·대리 점수, 잠근 평가 점수, 배포 정확성을 따로 보고한다.

## 9. 후보 1개 선택 절차와 최종 검증
1. 잠근 평가셋을 먼저 만든다 (4.4, 첫 후보: AI-OpenBMAT 미사용 발췌에서 모든 사용 트랙과 겹치는 발췌를 뺀 것 + 원천 archive 미사용 행).
   ID 해시를 잠그고 지표는 계산하지 않는다.
2. 개발 증거(A·B)로 X1 후보 중 1개(사전 등록 3개 중), X2(실행했다면)를 G1–G5로 거른다.
3. 통과한 후보 중 G1의 Δ가 가장 큰 1개를 **최종 후보**로 고정한다. 동률이면 변경이 작은 쪽(X1)을 고른다.
4. 잠근 셋에서 **최종 후보, S7 패키지, s7_new 패키지**를 한 번만 채점한다(G6). 두 패키지 모두 이 행을 학습하지 않았다.
5. 배포 검증(G7): CPU 검증, 강화 parity, (코드가 바뀌면) CUDA 검증.
6. 결과 반영: 모든 관문을 통과하면 슬롯 ③에 넣는다. 하나라도 실패하면 최종 후보를 버리고 계획대로 ③ W_new를 낸다.
   ①② (s7_new, W_newB)는 이 절차와 무관하게 이미 검증된 계획대로 제출한다. LB가 최종 점수이므로, 세 LB 결과는 그대로
   공식 성능으로 보고하고 오프라인 수치와 섞지 않는다.
