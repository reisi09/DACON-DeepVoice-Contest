## Decision

Keep the packaged M330 pipeline as the comparison control. First test **a small File relation trained on out-of-fold component evidence** because it needs no extra backbone inference. Then test **an aligned raw/stem residual music path trained on valid mixed examples** and refit the File relation only if that music change passes its gate. Run each change separately before combining them. Keep native-channel HTDemucs input and complete temporal coverage. Reuse the existing compact temporal head and existing joint-state formulas where appropriate; do not start with another foundation-model sweep or joint full fine-tuning of every expert.

Why: the recent experiment tested separate raw and stem music heads followed by constant probability averaging, plus a File classifier on temporal means. It did not test music authenticity conditioned jointly on aligned raw and stem evidence, nor a File classifier that retains sparse temporal events. Its direct File head traded natural-file quality for synthetic-mixture quality. Those results narrow the next hypothesis; they do not eliminate every learned fusion architecture.

## Objective mismatch and probability semantics

`graph_scoring.py:124-165` implements:

`0.45*(1-File EER) + 0.18*(1-Voice EER) + 0.27*(1-Music EER) + 0.05*Voice presence AUC + 0.05*Music presence AUC`.

Component EER eligibility uses **ground-truth presence**, never predicted presence (`:135-147`). Therefore conditional authenticity must remain independently useful on true-present files, even when the presence predictor is uncertain. Multiplying authenticity by predicted presence before exporting `VOICE_FAKE_PROB` or `MUSIC_FAKE_PROB` would change the target semantics. The current C08 and S2 outputs correctly keep them separate. B4 also returns conditional authenticity rather than unconditional fake mass.

The largest official term is File EER. Yet:

- Temporal music checkpoints minimize source/class-balanced music BCE or CE (`music_temporal.py:275-278`, `:321-355`). Head selection is not the official objective.
- Fast blend selection minimizes Music EER (`fast_h100_ablation.py:281-285`), while the direct File head selects CE (`:238-245`).
- V5 independent experts select component EER or presence AUC (`v5_training.py:244-260`). V5 fusion selects unweighted mean known-head BCE, even B4 trained with joint NLL (`v5_fusion_training.py:121-135`, `:195-200`, `:225-239`).
- B4's known-head BCE weighting changes with label availability; neither that BCE nor the joint NLL equals the five official weights.

A monotonic recalibration can preserve component EER while changing the rank of the **maximum of two products**, and thus changing File EER. A component improvement therefore neither guarantees nor rules out a File improvement. For a component-preserving File-only change, the known local weighted difference is exactly `0.45*(old File EER-new File EER)`; this can be assessed on existing complete File labels without pretending that the absolute official total is known. For a music-plus-File change with all other outputs identical, the identifiable difference is `0.45*ΔFile + 0.27*ΔMusic`. Fresh complete labels are still needed before claims about all five heads or official rank.

The latest test has 123 unknown relevant voice labels and 113 unknown voice-presence labels, so its total stays null (`fast-results/metrics.json:765-799`). Unknowns must not be silently relabeled real, absent, or baseline-predicted.

## Time coverage: distinguish an actual gap from an aggregation bottleneck

- Original/C08/M330 windows include the last full window and cover every sample; short files are tiled (`baseline_original/script.py:157-175`). V5 also uses a tail-anchored full grid (`v5_features.py:46-51`, `v5_training.py:173-180`). There is no missing-tail defect here.
- C08 loses within-window detail when MERT frame tokens are mean-pooled (`c08_submission.py:88`). Its three temporal convolutions operate on ordered 4.0375 s features, not on dense acoustic frames. `music_temporal.py:209-238` validates timestamps but the one-bin forward receives only features/masks, not actual time deltas. Neighboring slots can therefore have unequal spacing at the overlapping final window.
- S2 has a concrete **interior coverage gap**, despite retaining the tail. Eight samples are chosen from all five-second starts (`s2_eat_submission.py:32-38`). At exactly 60 s the starts are `0,10,15,25,30,40,45,55` s, covering 40 s and omitting four interior five-second spans. A sequential fake component entirely in an omitted span is inaccessible to the S2 music model. This is a plausible official failure mode, not a measured frequency of official errors.
- S2 training samples four windows from an activity-filtered pool of eight; evaluation uses an unfiltered fixed pool (`worker:249-298`). This differs from full-file music MIL and needs a sparse-fake stress panel before increasing model depth.
- V5 cached fusion trains on one deterministic ≤20 s context per original file and validates full files (`v5_features.py:54-79`). A temporal failure could reflect context/exposure mismatch. B4_joint further reduces training to first/last windows, so it cannot establish that full-length end-to-end fusion was thoroughly tested.
- V5 aligns expert start times, not equal-duration receptive fields: voice/presence windows are 64,600 samples, SONICS windows are 80,000 (`v5_experts.py:23-25`), all placed on the 64,600-sample timeline (`v5_features.py:117-123`). This is intentional start alignment but not exact same-span evidence; a proposed time-conditioned fusion should declare its window support explicitly.

## Separator and fullFT distinctions

Original separation reads the source file through `load_track` at the model's expected rate/channels (`baseline_original/script.py:264-267`). S2 reads 16 kHz mono first and then repeats/resamples it (`s2_eat_submission.py:44-45`, `:95`). Parent freshly verified official audio is already 16 kHz mono **or stereo**. Therefore do not explain S2's official behavior by presumed loss above 8 kHz. Stereo collapse and resampler/numerical differences remain testable. Preserving model weights does not preserve the input to the voice model.

The existing S2 preprocessing diagnostic holds recordings/weights fixed but all 24 saved inputs are 16 kHz mono (`fast-results/preprocessing_audit.json`). It therefore cannot measure loss of stereo information. Its score differences are not a causal explanation of a leaderboard score gap.

FullFT is genuinely deeper than last-layer tuning: `worker:362-370` freezes the encoder only for the frozen arm, otherwise leaves MERT frontend/Transformer trainable except an unused masking token; EAT keeps upstream fixed positions. Gradients flow through `encode_windows` (`:397-410`) and all trainable encoder/head tensors enter optimizer groups (`:443-451`), with frontend/early/late gradient checks (`:462-485`). Do not rebrand a partial-FT trial as fullFT, or suggest that the recorded fullFT arm merely trained the classifier.

HTDemucs adaptation is **fixed-teacher remix supervision**, not classifier-driven joint separation:

- Four parent-disjoint teacher stem examples make each remix (`fullft_separator.py:74-87`).
- All separator parameters minimize waveform L1 to those fixed pseudo-stems; four held-parent pseudo-remixes select the checkpoint (`:102-159`).
- Teacher sources are centered five-second crops from 16 kHz mono duplicated to stereo (`:230-247`). Teacher is released before fitting the student (`:251-272`).
- Saved artifacts show 41,984,456 trainable separator parameters with nonzero gradients, update L2 0.993006, and pseudo-validation L1 0.0116051→0.0113244 at step 250 (`fullft-results/separator_adaptation/gradient_evidence.json`, `history.json`). That proves optimization and teacher agreement, not true-stem accuracy or preservation of forensic cues.
- S0 EAT test Music EER changed 0.30000→0.25278 with adaptation; adapted S2 was not evaluated (`fullft-results/comparison.json:19-24`, `:59-63`). Packaged S2 uses original frozen HTDemucs (`submissions/S2_EAT/package_verification.json:13`).

## Data and cache risks to resolve before richer modeling

1. **Source shortcut remains plausible after group-disjoint splitting.** Fast train music contains 800 Echoes fake files versus 70 FMA and 73 NSynth real files. Validation has only 12 FMA; test only eight FMA plus 11 NSynth (`results/fast_h100_20260917/split_summary.json:2-60`). Class/source weighting controls loss mass, not source-origin correlation. `v7_ablation.py:60-81` equalizes fake-provider mass and caps NSynth; it cannot by itself remove codec, duration, recording, or instrumentation shortcuts. This is a risk, not proof the model uses a particular shortcut.
2. **Synthetic distribution is narrow.** `v6_data.py:98-117` makes equal four label combinations but repeats shorter parents with `np.resize`, normalizes both parents by RMS, caps length at 16 s, draws ±9 dB mixing level, and normalizes peak to .8. These controls do not cover natural stereo mixtures, sequential events, variable duration, natural compression, or low-level components. A model can learn a synthetic-domain rule that transfers poorly even without label leakage.
3. **Music crops must inherit only defensible labels.** V5 masks unsupported crop authenticity (`v5_dataset.py:184-189`); paired real-real splices exist as editing controls (`v5_features.py:165-179`). Temporal augmentation crops only a whitelist of full-track music sources (`temporal_augmentation.py:44-64`). New sequential partial-fake examples require event-level supervision or whole-bag labels; never mark every selected crop fake merely because the file contains one fake interval.
4. **Partial vocal truth is real uncertainty.** Existing mixture creation leaves real-speech-plus-fake-music voice truth unknown when the music may contain generated vocals (`v6_data.py:115`; `fast_h100_ablation.py:68-69`; `v5_dataset.py:212-214`). This behavior should be preserved. Distinguish instrumental-only fake music from singing when obtaining labels.
5. **Hashes protect identity, not representativeness.** Fast extraction verifies original audio and model weights, uses code/model/dtype/window/view/GPU identifiers, and writes cache/member receipts (`fast_h100_ablation.py:59`, `:103-109`, `:131-148`, `:190-192`). Original V6 cache identity additionally includes asset manifest, runtime code, package versions, and device (`v6_runtime.py:34-42`, `:93-97`). Future cache reuse must bind the actual separator path, channels, resampler, window policy, and every changed encoder checkpoint; an ID/shape match is not enough.
6. **Training cache is not an inference lookup.** Proposed inference must recompute evidence for each evaluator file. Train-derived folds, scalers, weights, and calibration parameters may be saved; evaluator-file predictions, neighboring evaluator files, or aggregate test statistics may not influence another file.

## Constrained main architecture and two alternatives

**Main candidate, after gates 1–2:** keep native-channel HTDemucs, fixed PANNs presence, fixed DF-Arena voice, and the existing M330 stem temporal head. Add one small **file-local, time-aligned raw/stem residual music correction**. Train it on parent-disjoint pure, simultaneous, sequential, and benign-processing controls with component labels only where supported. Train the File relation on OOF predictions from that candidate; selection uses the identifiable weighted difference and a complete external panel when available. Each final evaluator file is processed independently. Ensemble only small heads over shared encoder evidence if this beats a single head under the runtime budget.

This candidate is deliberately narrower than rebuilding every head: unchanged voice and presence outputs allow exact paired File/Music deltas despite current voice-label gaps. It does not claim baseline voice/presence are optimal; their errors are a separate, labeled follow-up.

**Alternative A — structured joint output:** reuse B4's nine-state marginalization when complete state supervision supports it. Replace its older B2 feature source with the current aligned evidence for a matched comparison. Presence and authenticity semantics stay explicit. Do not assume nine classes cure missing labels.

**Alternative B — EAT music replacement:** keep baseline native-channel voice path independent of EAT's music preprocessing; cover all music windows. Use the existing EAT checkpoint as a matched music-only challenger before any new training. This isolates encoder/coverage gains from the S2 voice-path change. Reusing the EAT representation is plausible; simply stacking EAT and MERT has no support until latency and complementary-error gates pass.

## Deployment and meaningful verification

Parent freshly verified official budget: L4 22.4 GiB VRAM, 28 GB RAM, six CPU cores, 60 min, 1,200 audio files, ZIP ≤10 GB and unpacked ≤32 GB. Audio is standardized 16 kHz, mono or stereo, 4–60 s, including telephony and multiple codecs. Any generated component makes the file fake; ordinary enhancement/noise removal/gain preserves real. Test-set weight updates, pseudo-label training, and cross-file prediction/statistic correction are forbidden. Official source verification belongs to the parent audit; these are not claims derived from local training code.

- The total budget averages **3 seconds per file including startup/decoding/model loads**, with length distribution affecting the true bound. A one-file A100 result or H100 training throughput cannot establish compliance.
- Dual raw/stem MERT reuses weights but roughly doubles its window encoding work; it does not double just the tiny classifier. Batch windows **within a file** to reduce overhead. Never batch-normalize across evaluator files or update test-time statistics. Any cross-file batching must first prove numerical independence, and simple file-local operation is the safer initial implementation.
- Current C08 computes presence as a separate pass and releases PANNs before the larger inference models (`baseline_original/script.py:228-241`; `c08_submission.py:57-65`). Preserve this memory advantage. V5 keeps all three experts plus separator resident (`v5_submission.py:393-406`); richer V5 deployment needs an actual peak-memory measurement.
- H100 EAT benchmark values (b1 6.606 GiB/11.53 songs/s; b4 10.942 GiB/32.53 songs/s) are **cached-waveform classifier training** with backward and AdamW, excluding separator and whole submission inference (`benchmark_fullft8_batching.py:33`; `fullft-results/performance/batch_benchmark.json:25`). Do not extrapolate them into L4 inference claims.
- Required verification has direct decision value: actual ZIP offline reload versus reference outputs; score stability when a file's position/neighbors change; known fake events in covered/omitted spans; stereo separator comparison with fixed models; component masks under absent/unknown truth; parent-group/PCM separation; nonzero gradient/update for each newly trainable branch; target L4 VRAM, host RAM, cold-start and 60-second worst-case duration/codec timing.
- The current S2 record explicitly marks full GPU/L4 1,200-file runtime unverified (`submissions/S2_EAT/runtime_verification.json:18-20`). No new architecture is deployment-ready until measured against the actual packaged path.

## Uncertainties and stop conditions

The present evidence cannot identify which component causes the official score gap, establish #1 attainability, measure natural stereo effects from mono-only diagnostics, or certify L4 execution. It also cannot resolve source shortcuts from group separation alone. Stop expanding architecture if the fresh natural-real panel reverses the local gain, OOF File fusion repeats the natural/mixed tradeoff, aligned raw correction is no better than a same-capacity control, or target L4 runtime fails. Keep the current package intact and preserve its artifact hashes until a replacement passes those gates.
