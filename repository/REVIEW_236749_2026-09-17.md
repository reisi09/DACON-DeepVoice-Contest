## 0. 결론 요약

1. 현재 위치는 177위 0.7396 (ADS 0.7119). 2차 평가 진출선(15위)은 0.8508, 1위는 0.8884. 남은 12일 안에 총점 +0.11이 필요하다. 지난 4일간 얻은 상승은 +0.008 (C08 0.7315 → M330 0.7396)이므로 같은 방식의 연장으로는 불가능하다.
2. 지금까지의 실험은 "고정 MERT 특징 위의 8.8만 파라미터 head"를 100회 넘게 비교하는 데 자원을 썼는데, 로컬 지표가 공식 점수를 예측하지 못한다는 것이 기록 자체에서 반복 확인된다. 즉 대부분의 비교는 노이즈를 최적화했다.
3. 병목은 head 구조가 아니라 (a) 음성 브랜치를 한 번도 개선하지 않은 것, (b) 음악 학습 데이터가 실제 61곡 + 단일 생성기 계열이라는 것, (c) 가중치 0.45인 File 결합에 캘리브레이션이 없는 것, (d) 테스트 조건(16 kHz 표준화, 전화채널, 코덱, 혼합)을 흉내내지 않은 것이다.
4. 제안: 검증셋을 공식 테스트 사양대로 다시 만들고, 음성은 공개 post-trained 탐지기(AntiDeepfake + DF-Arena) 앙상블로 즉시 교체, 음악은 데이터 10배 확장 + 전층 가중합 MIL head + 스펙트로그램 CNN 앙상블, File은 캘리브레이션된 noisy-OR. 매일 3회 제출을 실제로 쓰는 실험 루프로 전환.

## 2. 문제점

### 2.1 로컬 지표가 공식 점수를 예측하지 못한다 (가장 큰 문제)

| 제출 | 로컬 Music EER | 로컬 File EER | 공식 총점 |
|---|---:|---:|---:|
| AST_LAST_BLOCK (dev 122) | 0.147 | 0.156 | 0.6453 |
| AST epoch17 확장 (dev) | 0.088 | 0.106 | 0.6175 (full1029) |
| S2 EAT fullFT (test 190, real 12개) | 0.168 | — | 0.6379 |
| C3 (dedup 190) | 0.3139 | 0.3160 | 0.6844 |
| C08 seed41 (같은 190) | 0.3139 | 0.3160 | 0.7315 |
| M330 MLP 3-seed 평균 | 0.220 | 0.267 | 0.7396 |

C3와 C08은 같은 패널에서 소수점 4자리까지 같은 File/Music EER인데 공식 점수는 0.047 차이다. 로컬 EER이 가장 좋았던 AST·S2는 공식에서 최하위였다. 이 표 하나로 "historical test 190에서 0.01~0.03 개선"을 근거로 한 선택은 전부 무효다. 150개 음악 test에서 파일 1개 = 0.67%p이므로, compact 37회·methods 48회·resolution 12회·MERT330/cosine/AF 18회 fit에서 읽어낸 차이 대부분은 시드 표준편차(0.01~0.03) 이내다.

### 2.2 학습 데이터가 테스트 분포와 다르다

- 실제 음악: FMA 고유 원곡 61개 + NSynth 4초 단음(실제 클래스의 61.8%). 단음 악기음은 "음악"이 아니다. 길이만으로 group-OOF AUC 0.894가 나온다는 것은 라벨이 원천과 길이로 지름길 학습된다는 뜻이다.
- 가짜 음악: Echoes 계열 946개가 거의 전부, 후에 MusicGen/AudioLDM 일부. 테스트에 있을 가능성이 큰 Suno/Udio/ACE-Step/DiffRhythm/Stable Audio/상용 API 출력이 없다. SVDD 2024에서는 학습에 없던 상용 가창 합성기(ACESinger)에 대해 상위 팀 전원이 EER 약 50%였다. 생성기 다양성이 곧 성능이다.
- 음성: 진위 라벨 unknown이 1,116/1,516. 한국어 0, 전화채널 0, MLAAD-tiny만 사용. "딥보이스 범죄 대응" 대회인데 음성 브랜치는 한 번도 학습·개선되지 않았다. V6에서 DF-Arena를 XLS-R+AASIST(ONNX)로 바꾼 뒤 known-voice EER이 0.17 → 0.43으로 악화됐고 그 상태로 C3가 제출됐다.
- 혼합: 학습 0개, tune 100/248, test 100/150. 테스트는 혼합(동시·순차)이 정식 유형이다.
- 대역·채널 정합: 테스트는 전부 16 kHz 표준화(8 kHz 이상 정보 없음), 모노/스테레오 혼재, MP3/WAV/FLAC, 일부 전화채널이다. 학습 파이프라인이 이를 동일하게 흉내내지 않으면 "고주파 유무"나 "원본 SR" 같은 지름길을 배운다. MERT는 24 kHz 모델이므로 16k → 24k 업샘플 입력이 학습과 추론에서 동일했는지 기록이 없다.

### 2.3 검증 설계의 자기모순

- historical test 190개를 100회 이상 재사용했고, sealed는 결국 full 학습에 흡수됐다. 독립 확인셋이 없다.
- S2 test는 실제 음악 12개(파일 1개 = 8.3%p EER)인데 이를 근거로 제출했다.
- redesign A/B는 129개/12그룹으로 noisy-OR를 판정했다. bootstrap 구간이 0을 포함하는 것은 설계상 당연하다. 판정력이 없는 실험은 실행 자체가 낭비다.
- 해시·parity·재현성 감사는 훌륭하지만, 통계적 검정력이 없는 비교를 정밀하게 재현하고 있다. 검정력은 파일 수가 아니라 독립 원천·생성기 수에서 나온다.

### 2.4 모델링 자원 배분

- 노력의 대부분이 Conv 층수·채널, cosine, prototype, LS, plateau, R1/R8 같은 head 미세 변수에 들어갔다. 16설정 × 3 seed의 historical 차이는 SD 이내다.
- MERT는 마지막 층만 사용했다. SSL 기반 탐지기의 표준(SLS, 층 가중합)은 중간층 활용이다.
- 윈도우 max pooling은 60초 실제 곡에서 윈도우 하나만 튀어도 오탐을 만든다. 문서의 `Empower Thee` 사례가 그 경로다.
- 제출한 5-fold M330은 NSynth mass 0.05인데 tune에서 고른 설정은 mass 0이다. 설정 드리프트.
- 전체 미세조정(S0~S2)은 파일 900개, patience 3, 최대 20 epoch, batch 1×8, 인코더 LR 1e-5로 설계돼 epoch 1~3에서 과적합했다. "fullFT가 frozen보다 나쁘다"가 아니라 "900개로는 fullFT를 할 수 없다"는 결과다. 최근 대회 상위 시스템은 모두 수만~수십만 발화로 SSL을 미세조정한다.
- File 결합(0.45)에 캘리브레이션이 없다. DF-Arena 확률과 자체 음악 head 확률의 스케일이 다른데 max(Pv·Sv, Pm·Sm)로 합친다. 문서 13.3의 temperature 실험이 이미 증상을 보여준다(Music EER 불변, File EER 변동).

### 2.5 제출 전략

- 로컬 검증이 무효인 상황에서 리더보드가 유일한 유효 검증인데 가장 덜 썼다.
- B_full1696(6.3 GB)는 만들고 제출하지 않았다. 다만 이 패키지는 MERT를 raw/stem 2회 통과시키므로 L4 60분 예산이 검증되지 않았다. H100에서 7파일 120윈도우 35초였다면 1,200파일은 L4에서 60분을 넘길 가능성이 크다. 제출 전 Colab L4로 시간을 실측해야 한다.

### 2.6 확인해야 할 잠재 버그

1. AST 제출이 1,200파일을 81초에 처리했다. AST 고정 입력이 10.24초이면 파일 앞 10초만 평가했을 가능성이 있다. 후반부 부분 생성은 전부 놓친다.
2. 학습 원본 SR(AudioLDM/Echoes 16 kHz vs FMA 44.1 kHz)이 라벨과 상관되면 대역폭 지름길이 생긴다. 클래스별 spectral rolloff 히스토그램으로 확인.
3. 스테레오를 평균(mid)만 쓰면 side 성분이 사라진다. 채널별 추론 후 로짓 평균이 안전하다.
4. 라벨 규칙: 운영진 답변에 따르면 신경망 코덱 재합성·노이즈 제거·소스 분리만 적용된 실제 음원은 REAL이다. DF-Arena-1B와 AntiDeepfake는 Codecfake/LibriTTS-R(신경망 복원)을 FAKE로 학습했다. 테스트에 "신경망 후처리된 REAL"이 있으면 오탐 경로가 된다. 로컬에 enhanced-real 셋(DeepFilterNet·Resemble-Enhance 등 적용)을 만들어 점검하고, 필요하면 소량 미세조정으로 REAL로 정렬한다.

## 4. 제안 구조: 스템 분리 + 캘리브레이션 앙상블 MIL 탐지기

```
입력 파일 (MP3/WAV/FLAC, 16 kHz, 모노/스테레오)
 └─ 디코드 → 16 kHz 확인 → 채널별 보존(L/R/mid)
     ├─ PANNs + 스템 에너지비 → VOICE_PRESENT, MUSIC_PRESENT (기존 유지)
     ├─ HTDemucs → vocals 스템 / accompaniment 스템 (파일당 1회)
     ├─ 음성 브랜치 (vocals 스템, 음악 존재 낮으면 raw)
     │    ├─ DF-Arena-1B (기존)                       ┐
     │    ├─ AntiDeepfake XLS-R-1B (zero-shot)         ├─ 윈도우 8 s / hop 4 s
     │    └─ (선택) MMS-300M-AntiDeepfake 경량 미세조정 ┘   top-k 평균 pooling → Platt 캘리브레이션 → 평균 → Pv
     ├─ 음악 브랜치 (accompaniment 스템 + raw)
     │    ├─ MERT-330 frozen, 25층 가중합 + attention-MIL head (약 15만 파라미터)
     │    ├─ log-mel(16 kHz, 64 mel) 6층 CNN, 처음부터 학습          → 각각 캘리브레이션 → 평균 → Pm
     │    └─ CLAP(music) 임베딩 + 로지스틱 회귀
     └─ File = 1 − (1 − Pv·gV)(1 − Pm·gM)   (g = 존재 확률 소프트 게이트, 모두 캘리브레이션된 값)
```

### 4.1 브랜치별 설계

음성
- zero-shot 앙상블만으로도 개선 기대. AntiDeepfake는 가창 데이터를 학습하지 않았으므로 노래 보컬에서는 DF-Arena(CtrSVDD 학습) 가중치를 높인다.
- 경량 미세조정을 한다면 MMS-300M-AntiDeepfake의 마지막 4층 + head만, 또는 hidden states를 고정하고 SLS식 층 가중 head만 학습. 데이터: MLAAD ko/ja/zh/en, Codecfake 일부, CtrSVDD/SingFake 가짜 가창, 자체 생성 한국어 TTS/VC(XTTS-v2 ko, MeloTTS, CosyVoice2, F5-TTS ko, GPT-SoVITS, RVC/Seed-VC). 실제: M-AILABS, Zeroth-Korean, KSS, FLEURS-ko, Common Voice ko, CtrSVDD/SingFake bona fide, 그리고 신경망 노이즈 제거를 적용한 실제 음성(REAL 라벨).
- 전화채널: 300~3,400 Hz 대역 제한 + 8 kHz 왕복 + G.711/AMR-NB/Opus 저비트율 + RawBoost 계열을 학습 증강으로.

음악
- 실제: FMA-medium(25k곡, CC), MTG-Jamendo(55k곡, CC), MUSDB18 반주. 보컬 유무를 Demucs 보컬 에너지로 태깅해 "음악 단독"과 "혼합 실제" 둘 다 확보. NSynth는 제외.
- 가짜: SONICS(Suno/Udio)에서 Demucs로 반주만 뽑은 버전과 원곡 버전, FakeMusicCaps(MusicGen/AudioLDM2/Stable Audio/MusicLDM/Mustango), 자체 생성 1~2천 클립(ACE-Step, Stable Audio Open Small, DiffRhythm, MusicGen). 디코더 계열을 최대한 섞는다.
- 전부 16 kHz로 먼저 리샘플한 뒤 4~60초 크롭, MP3/AAC/Opus 재인코딩, 게인, 모노/스테레오, 전화채널 확률 적용. 학습·검증·추론 모두 같은 전처리.
- 코덱 재합성 실제 음악은 대회 정의상 REAL이다. Deezer식 "재합성 = 가짜" 라벨은 쓰지 않고, 소량을 REAL hard negative로 넣어 코덱 아티팩트만 보는 지름길을 막는다.
- pooling: max 대신 attention-MIL + top-30% 평균. 부분 생성(스플라이스)은 bag 라벨만, 전체 생성/전체 실제는 윈도우 라벨도 부여.

File 결합
- 각 브랜치 로짓을 group-held-out dev의 OOF 예측으로 Platt 캘리브레이션한 뒤 noisy-OR. max와 noisy-OR 중 어느 쪽이 나은지는 리더보드로 1회 비교.
- 규칙상 다른 파일의 통계로 보정(Z-norm 등)은 금지. 캘리브레이션 파라미터는 학습 시점에 고정한다.

## 5. 검증 프로토콜 재설계

1. 공식 사양을 그대로 흉내낸 pseudo-test(약 1,000파일)를 만든다: 4~60초, 16 kHz, 모노/스테레오, MP3/WAV/FLAC, 전화채널 10~20%, 유형은 음성 단독·음악 단독·혼합(동시·순차), 라벨 조합은 실제+실제, AI음성+실제음악, 실제음성+AI음악, AI노래(둘 다 가짜), 부분 생성 스플라이스.
2. 분할은 원천·화자·아티스트·생성기 단위로 분리한다. 생성기 하나(Suno 또는 Udio, TTS 계열 하나)는 완전히 홀드아웃한다. 목표는 "미학습 생성기 EER"이다.
3. 지표는 공식 산식(argmin |FPR − FNR|, drop_intermediate=False)을 그대로 계산한다.
4. 하루 3회 제출을 "한 번에 한 요인" 원칙으로 쓴다. 제출 장부에 가설·변경 요인·로컬 pseudo-test 점수·공식 점수를 한 줄씩 기록하고, 로컬과 공식의 상관을 매번 갱신한다. 상관이 안 나오면 pseudo-test를 고친다.
5. 150개 test에서 0.01 차이로 의사결정하지 않는다. 최소 독립 원천 300개, 생성기 5개 이상 없이는 비교 실험을 시작하지 않는다.

## 8. 코드 스니펫

### 8.1 MERT 전층 가중합 + attention-MIL head

```python
import torch, torch.nn as nn

class LayerWeightedMIL(nn.Module):
    def __init__(self, n_layers=25, d=1024, h=128, p=0.2):
        super().__init__()
        self.layer_logits = nn.Parameter(torch.zeros(n_layers))
        self.proj = nn.Sequential(nn.LayerNorm(d), nn.Linear(d, h), nn.GELU(), nn.Dropout(p))
        self.att = nn.Sequential(nn.Linear(h, h // 2), nn.Tanh(), nn.Linear(h // 2, 1))
        self.cls = nn.Linear(h, 1)

    def forward(self, hs, mask):
        # hs: [B, L, W, D] (층, 윈도우별 평균 특징), mask: [B, W] 유효 윈도우
        w = torch.softmax(self.layer_logits, 0).view(1, -1, 1, 1)
        x = self.proj((hs * w).sum(1))                       # [B, W, h]
        a = self.att(x).squeeze(-1).masked_fill(~mask, -1e4)
        a = torch.softmax(a, -1)
        bag = self.cls((a.unsqueeze(-1) * x).sum(1)).squeeze(-1)   # bag 로짓
        inst = self.cls(x).squeeze(-1).masked_fill(~mask, -1e4)    # 윈도우 로짓
        return bag, inst

def topk_mean(inst, mask, frac=0.3):
    out = []
    for row, m in zip(inst, mask):
        v = row[m]
        k = max(1, int(round(frac * v.numel())))
        out.append(v.topk(k).values.mean())
    return torch.stack(out)

# 손실: BCE(bag) + 0.5 * BCE(topk_mean) ; 전체 가짜/전체 실제 bag은 윈도우 라벨에도 BCE
```

### 8.2 캘리브레이션 + File 결합 (dev OOF 로짓으로 학습, 테스트 통계 사용 안 함)

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

cal_v = LogisticRegression(C=1.0).fit(dev_voice_logit.reshape(-1, 1), dev_voice_y)  # Platt
cal_m = LogisticRegression(C=1.0).fit(dev_music_logit.reshape(-1, 1), dev_music_y)

def fuse(lv, lm, p_voice_present, p_music_present):
    pv = cal_v.predict_proba([[lv]])[0, 1] * p_voice_present
    pm = cal_m.predict_proba([[lm]])[0, 1] * p_music_present
    return dict(FILE=1 - (1 - pv) * (1 - pm), VOICE=pv, MUSIC=pm)   # noisy-OR; max와 LB로 1회 비교
```

## 9. 라이선스·2차 평가 메모

- AntiDeepfake, MLAAD 등 CC BY-NC-SA 자원은 운영진 답변(2026-08-27)으로 사용 가능. 다만 "수상작 독점권리 조항" 토크 글을 읽고 NC/SA 자원과의 충돌 여부를 확인할 것.
