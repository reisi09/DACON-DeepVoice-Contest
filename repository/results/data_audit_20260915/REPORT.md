# V6 학습 데이터 품질 분석

2026-09-15, 로컬 CPU 분석. GPU를 재개하거나 원본 데이터·라벨을 변경하지 않았다.

## 판단

손상 파일보다는 **진짜·가짜의 출처 차이, 학습·평가 분포 차이, 평가 자료의 중복**이 먼저 해결할 문제다. 현재 자료로 300 epoch를 더 학습하기 전에 비교 데이터와 샘플링을 정비해야 한다. 다만 이번 분석만으로 MERT의 실패 원인이 특정 데이터 하나라고 단정할 수는 없다.

## 범위와 방법

- train 1,516개, dev 210개, sealed 210개, 총 1,936개 WAV를 직접 읽었다.
- 전체 파형의 PCM SHA-256, 샘플링 주파수·채널, 유한값, 길이, RMS, peak, 무음·0 샘플 비율, DC offset, zero-crossing rate를 계산했다.
- 스펙트럼 중심과 6kHz 이상 에너지 비율은 파일마다 균등 배치한 4,096-sample 구간 16개로 측정했다.
- source group·artist·speaker·parent 기록과 정확히 동일한 PCM을 기준으로 분할 간 중복을 확인했다. 유사하지만 동일하지 않은 재인코딩 음원 전체를 찾아냈다는 의미는 아니다.
- V6 학습·평가 기록에서 로컬과 대응하는 1,726개 입력의 PCM 해시를 비교했다. 클라우드에서 생성한 결합기용 혼합 80개는 이 파형 검사에 포함하지 않았다.
- 저장된 V6 개발 예측을 ID로 결합해 기존 지표를 재현했다. sealed의 모델 예측은 새로 계산하지 않았다. sealed를 미사용 최종 holdout으로 인증하지 않는다.

## 1. 진짜 음악 구성과 라벨이 강하게 얽혀 있다

| 학습 데이터 | 음악 라벨 | 파일 수 | 길이 중앙값 |
|---|---|---:|---:|
| FMA | 진짜 | 70 | 230.87초 |
| NSynth | 진짜 | 100 | 4.00초 |
| Echoes | 가짜 | 946 | 77.39초 |

전체 음악 1,116개에서 진짜는 170개, 가짜는 946개다. 진짜의 58.8%가 NSynth다.

실제 V6 음악 분류층 학습 자료 823개는 **FMA 진짜 52개, NSynth 진짜 84개, Echoes 가짜 687개**다. 진짜 136개 중 NSynth가 61.8%다. V6는 같은 클래스의 파일에 동일 가중치를 주므로 진짜 클래스의 손실 가중치도 NSynth에 61.8% 배분된다.

V4의 `v4_training_data.py::_weights`에는 NSynth의 전체 샘플링/손실 질량을 0.05로 제한하는 처리가 있었으나 V6의 `fit_music`에는 출처별 가중치가 없다. 클래스 균형만 맞춰도 출처 불균형은 남는다.

심각도: 높음. 구성에 대한 확신은 높음, 성능 하락의 인과관계는 미확인.

## 2. 위조 흔적 외의 간단한 특성으로 학습 라벨이 구분된다

V6의 823개 학습 음악에서 fake=1 라벨과의 점이연 상관계수:

| 특성 | r |
|---|---:|
| 정확히 0인 샘플 비율 | -0.483 |
| RMS -50dBFS 미만인 100ms 구간 비율 | -0.400 |
| Zero-crossing rate | +0.212 |
| RMS dBFS | +0.208 |
| 파일 길이 | -0.037 |

길이는 진짜 쪽에 짧은 NSynth와 긴 FMA가 동시에 있어 전체 선형 상관이 작다. 단순히 r가 작다는 이유로 길이 편향이 없다고 해석하면 안 된다.

길이·RMS·quiet 비율·0 샘플 비율·ZCR·스펙트럼 중심·고주파 에너지 비율 7개로 로지스틱 회귀를 학습했다. 그룹 5-fold OOF 평가에서 scaler는 fold의 학습 자료에만 맞췄고, 같은 원본 그룹이 양쪽에 겹치지 않음을 확인했다.

| 진단 모델의 학습 대상 | 그룹 OOF AUC | 개발 음악 단독 50개 AUC |
|---|---:|---:|
| 음악 전체 1,116개, 7개 특성 | 0.8639 | 0.5500 |
| V6 실제 학습 823개, 7개 특성 | 0.8783 | 0.5450 |
| NSynth 제외 1,016개, 길이만 사용 | 0.8939 | 0.5000 |

학습 자료 내부의 구분력은 높지만 개발 자료로 옮기면 거의 무작위 수준이다. NSynth만 빼는 것으로 해결되지 않으며 FMA와 생성 음악의 길이 차이도 통제해야 한다. 개발 음악 단독 자료는 진짜 10개·가짜 40개로 작으므로 정밀한 성능 추정이 아니다.

진단 특성은 원본 전체 파일에서 계산했고 V6의 MERT는 분리 음악 구간을 입력받는다. 이 결과는 데이터 편향의 증거이며, MERT가 해당 특성을 사용했다는 직접 증거는 아니다. OOF 값은 fold 간 확률을 합친 탐색 지표다.

## 3. 평가용 부분 위조 패널에 정확한 중복이 있다

- dev: splice 40개 중 실제로는 20개 PCM, 각 2회 반복.
- sealed: 동일하게 splice 40개 중 20개 PCM, 각 2회 반복.
- train 안에서는 정확히 중복된 PCM이 발견되지 않았다.
- 분할 사이의 정확한 PCM 중복, 기록된 원본·부모·아티스트·화자 중복은 발견되지 않았다.
- 중복 쌍의 알려진 라벨에는 충돌이 없고, dev 중복 쌍의 V6 파일·음악 예측도 동일하다.

원인은 `prepare_v4_data.py::_derivatives`가 10개 음악 그룹을 `range(20)`과 나머지 연산으로 두 번 순회하고, `splice`가 같은 입력에 결정적인 crop을 적용하기 때문이다. ID는 다르지만 파형은 같다.

| V6 개발 평가 | 기존 210개 | PCM 중복 제거 190개 |
|---|---:|---:|
| 파일 EER | 38.57% | 33.59% |
| 음악 EER | 48.29% | 46.67% |

이는 모델 개선이 아니다. 어려운 splice 패널의 상대 가중치가 달라져 수치가 바뀐다. 앞으로 베이스라인과 모든 후보를 같은 중복 제거 ID 목록으로 평가해야 한다. 기존 210개 점수도 추적용으로 병기한다. `dev_unique_ids.csv`는 PCM별 사전순 첫 ID를 남긴 190개 목록이다.

심각도: 높음. 원인과 영향 모두 재현됨. 원본 평가 파일은 삭제하지 않았다.

## 4. 손상보다는 저정보량 음원 후보가 있다

1,936개 모두 읽기·16kHz mono·유한값·기록된 PCM 해시가 일치했다. V6 기록과 비교한 1,726개도 PCM 불일치가 없었다. 검사한 형식적 라벨 논리 위반은 없었다. 실제 음원을 사람이 듣고 모든 라벨의 의미를 인증한 것은 아니다.

12개 학습 음원은 전체 100ms 구간의 80% 이상이 -50dBFS 미만이었다. NSynth 10개, Echoes 2개다. 이 기준은 무음에 가까운 구간이 많은 파일을 찾는 휴리스틱이며, 악기 감쇠·휴지부도 포함한다. 완전 무음이나 손상이라고 부르면 안 된다. `audio_review_candidates.csv`에 ID·경로·수치를 기록했다.

## 5. V6는 혼합과 미지 생성기에서 특히 약하다

| 개발 부분집합 | 파일 수 | 음악 EER |
|---|---:|---:|
| 학습에 등장한 생성기 + 진짜 음악 | 40 | 31.67% |
| 학습에 없는 생성기 + 진짜 음악 | 20 | 50.00% |
| 음성·음악 혼합 | 80 | 52.50% |
| 부분 위조 | 40 (고유 PCM 20개) | 50.00% |

서로 독립적인 대규모 평가가 아니다. seen/ood 평가는 같은 진짜 10개를 공유하고, 혼합·부분 위조 자료도 같은 원본에서 파생된다. 특히 `_derivatives`는 가짜 음악에 `music_ood` 부모를 사용하므로 혼합 처리 실패와 미지 생성기 실패가 얽혀 있다. 혼합만이 원인이라고 분리해 주장할 수 없다.

개발 음악 오차와 길이·quiet 비율의 Spearman 상관은 각각 0.040, -0.085였다. 몇 개의 무음 파일만 제거하면 개발 오류가 해결된다는 근거는 없다.

## 다음 4시간 비교 실험에 반영할 순서

1. 동일 PCM 중복 제거 목록으로 베이스라인과 V6 점수를 먼저 고정한다. 이미 사용한 개발 자료를 새로운 최종 검증이라고 부르지 않는다.
2. 우선 같은 MERT 동결 모델에서 데이터 처리를 바꿔 비교한다. NSynth를 제외한 조건과 낮은 비중으로 제한한 조건, 같은 길이·같은 개수의 구간을 쓰는 조건을 비교한다. 전부 한 번에 바꾸면 각각의 효과를 알 수 없으므로 순차 비교한다.
3. 진짜 음악은 독립 아티스트 수를 늘리고, 가짜 음악은 생성기별 가중치를 맞춘다. 기존 파일을 반복 복제하는 것으로 독립 자료 수를 늘렸다고 계산하지 않는다.
4. 짧은 진짜 음악·단독 악기·긴 곡을 분리해 보고, 12개 저정보량 후보는 청취 또는 구간 확인 뒤 사용 정책을 정한다. 잘못 예측했다는 이유만으로 라벨을 바꾸거나 파일을 제거하지 않는다.
5. seen/ood 생성기와 원본/혼합 조건을 교차한 평가로 원인을 분리한 뒤, 남은 A100 예산으로 MERT 미세조정과 CNN 후보를 비교한다.

## 산출물과 재현

- `Data_quality_audit.ipynb`: 계산 코드와 실행 결과, 그래프.
- `summary.json`: 지표·무결성·입력 버전·분할별 수치.

- `dev_unique_ids.csv`, `dev_duplicate_ids.csv`: 개발 PCM 중복 제거 기준.
