1~6번 계산을 완료했고 H100은 stopped/standby 상태입니다. 실행 요청부터 결과 회수·정지까지 24.35분, 노트북 실행은 약 12분이었습니다. 결과 ZIP 45,135,528바이트와 내부 768개 파일의 SHA-256을 확인했습니다. 실행 노트북의 코드 셀 7개에 실행 번호가 있고 오류 출력은 없습니다. GPU를 추가로 시작하지 않았습니다.

이번 후보를 기존 M330 대신 제출할 근거는 부족합니다. 새 음악 자료를 추가하면 개발셋은 좋아졌지만 최종 확인셋에서 그대로 유지되지 않았습니다. 혼합 자료를 추가한 후보는 MP3 음질에서 개선됐고, 전화 음질과 일부 길이의 음악 판별에서는 악화됐습니다. 다음 학습의 우선순위는 음악 head 반복 학습보다 혼합 음원에서의 음성 판별 오류입니다.

아래 수치는 공식 리더보드 점수가 아닌 로컬 EER이며 낮을수록 좋습니다. 기본·MP3·전화 음질은 같은 최종 확인 원본 29개를 비교했습니다. 실제 음악 13곡, 가짜 음악 8곡, 실제·가짜 음성 8개이며, 독립 아티스트·곡·화자 그룹은 22개입니다. 음성 8개는 한 화자의 4쌍이므로 음성 일반화를 판단하기에는 부족합니다.

실험별 판단은 다음과 같습니다.

1. 새 검증 자료: 원본 136개에서 파생 음원 839개를 구성했고, 동일 오디오를 공유해 735개만 특징 추출했습니다. train/dev/test 원본은 78/29/29개입니다. 기존 B 전체 재학습 자료와 겹치지 않도록 기록된 아티스트·화자·원본 해시를 확인했습니다. 사전학습 중복이나 미기록 출처 중복까지 배제한 것은 아닙니다.
2. File 결합식: 기본 최종 확인셋에서 B noisy OR 10.05%, B max 7.11%, 같은 구간의 음성 증거를 쓴 noisy OR 10.05%였습니다. 개발셋에서는 모두 17.16%로 같았습니다. 시간 정렬만으로 일관된 개선을 확인하지 못했습니다. 최종 확인 결과를 보고 max를 새 승자로 선정하지 않습니다.
3. 정답 대체 진단: 개발셋의 음악 라벨이 있는 동일 21개에서 MUSIC_FAKE만 정답으로 바꾸자 File EER가 24.04%에서 0%로 줄었습니다. 음악 진위 판별을 개선할 여지가 있습니다. 반면 MUSIC_PRESENT를 정답으로 바꾸면 전체 개발셋 File EER가 17.16%에서 41.42%로 악화됐습니다. 존재 확률이 결합식에서 가중치 역할도 하므로 이 결과를 단순히 존재 분류기의 품질 순위로 해석하면 안 됩니다. 음성 정답 대체는 화자 한 명의 8개 파일에서만 가능했습니다.
4. 새 음악 자료 추가: B 구조·seed 41·17 epoch를 유지하고 기존 1696개에 train 음악 62개를 추가했습니다. 실제 보컬·장르를 청취 검수해 선별한 하드네거티브 실험은 아닙니다. 개발 File EER는 7.11%로 좋아졌지만 최종 확인 File EER는 17.16%, Music EER는 27.88%였습니다. 개발셋 개선만으로 학습량을 늘리면 안 되는 사례입니다.
5. 혼합 자료 추가: 같은 조건에서 train 혼합 음원 56개를 더해 1814개로 학습했습니다. seed 41의 기본 최종 확인 File EER는 7.11%였습니다. 실제·가짜 음성과 실제 음악을 섞은 최종 확인 8개에서는 File EER가 기존 B 50%에서 단일 seed 25%로 줄었지만, 3-seed 평균은 다시 50%였습니다. 이 작은 실험에서는 ensemble이 항상 낫지 않았습니다.
6. 길이·음질: 세 길이가 모두 있는 동일 원본 19개를 비교하면 4초 File EER는 M330 19.87%, 기존 B와 새 3-seed 모두 32.05%였습니다. 60초 Music EER는 기존 B 3.85%, 새 3-seed 16.03%로 악화됐습니다. MP3에서의 개선을 모든 조건으로 확대할 수 없습니다. 코덱 실험은 디코딩된 파형의 열화를 비교했으며 실제 제출 코드의 네이티브 MP3 입력 처리를 검증한 것은 아닙니다.

추가 CPU 분석에서는 가짜 파일만 있어 EER를 계산하지 못했던 짧은 삽입 실험에 같은 실제 배경 원본을 대조군으로 붙였습니다. 이는 결과를 본 뒤 수행한 진단이며 후보 선택에는 사용하지 않았습니다. 3초 가짜 음성 삽입은 기존 B와 새 3-seed 모두 File EER 25%, 3초 가짜 음악 삽입은 모두 37.5%였습니다. 음성 삽입은 연결된 독립 그룹이 하나라 일반화 근거로 쓸 수 없습니다. 음악 삽입은 8개 연결 그룹입니다. 원래 보고서의 지표 200개는 저장된 예측과 라벨을 다시 결합해 정확히 재현했습니다.

중요한 오류 단서는 음성을 음악과 섞었을 때 나왔습니다. 최종 확인셋의 실제 음성 4개는 단독 입력에서 VOICE_FAKE 확률이 0.005~0.010이었지만, 실제 음악과 섞으면 0.780~0.943으로 뛰었습니다. 실제 음악 자체의 MUSIC_FAKE 확률도 이 혼합 파일에서 0.263~0.946이었습니다. 음성 branch를 고정한 채 음악 head만 바꾸는 실험으로 해결할 수 있는 범위가 제한됩니다. 원음·분리 보컬을 청취해 성분 라벨을 확인한 뒤, 분리 과정과 음성 분류기의 오류를 나눠 점검해야 합니다.

자동 선택도 주의해서 해석해야 합니다. 개발 기본셋에서 새 음악 후보와 혼합 후보는 File/Music EER가 동점이었습니다. 코드의 `max((gain, name))`가 이름 순서로 혼합 후보를 선택했습니다. 이는 혼합 후보가 더 좋다는 통계적 근거가 아닙니다. 실제로 실행된 선택과 결과는 그대로 보존했습니다. 다음 실행에서는 동점 처리와 혼합·길이·음질 악화 시 탈락 기준을 미리 고정해야 합니다.

다음 단계는 GPU 없이 실제·가짜 음성 혼합 쌍의 원음과 분리 보컬을 검수하고, 올바른 음성 라벨 및 화자 수를 늘리는 것입니다. 그다음 기존 캐시와 동결된 encoder를 활용하는 작은 음성 보정 head를 비교합니다. 기본 File EER만으로 선택하지 않고 혼합 파일, 4초, MP3, 전화 음질의 악화 여부를 함께 보며, 동점이면 더 작은 학습 구성을 유지합니다. 이번 최종 확인셋은 이미 열었으므로 이후 튜닝의 새로운 독립 확인셋으로 재사용하면 안 됩니다. 새 encoder와 전체 미세조정은 이 문제가 개선된 뒤 검토합니다.

모든 라벨은 출처 메타데이터 또는 합성 구성에 근거하며 독립 청취 검수가 끝난 자료가 아닙니다. FMA 실제 음악과 SONICS 가짜 음악의 출처 편향도 남습니다. 음악 자료의 VOICE_PRESENT/VOICE_FAKE는 모르면 비워 두었고 공식 총점은 null입니다. L4 제출 실행과 리더보드 향상은 검증하지 않았습니다.
