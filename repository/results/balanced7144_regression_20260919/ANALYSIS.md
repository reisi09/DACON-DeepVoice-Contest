# Balanced7144 점수 하락 분석 — 2026-09-19

현재 확인된 문제는 데이터 개수보다 **음성·음악 분기의 결합 오류, 출처·길이와 정답의 결합, 검증 설계, 동시에 바뀐 학습 조건**에 있다. 이 문제들은 실제 코드와 검증 예측에서 확인했다. 다만 공개 제출 결과에는 세부 EER와 개별 예측이 없어, 각각이 공식 점수 하락에 얼마나 기여했는지는 아직 분리할 수 없다.

## 1. 음악 파일을 음성 분기가 가짜로 판정하는 오류

현재 파일 점수는 `max(voice_presence × voice_fake, music_presence × music_fake)`다.

음악 검증 파일 750개에서 재계산한 결과:

| 점수 | EER |
|---|---:|
| 음악 분류 확률만 사용 | 8.6573% |
| 음악 존재 확률 × 음악 분류 확률 | 10.2664% |
| 실제 제출 방식의 파일 점수 | 15.8711% |

진짜 음악 302개 중 임계값 0.5에서 파일 점수가 가짜로 판정한 것은 70개다. 이 중 **52개는 음악 분기의 곱 점수가 0.5 미만인데 음성 분기의 곱 점수가 0.5 이상**이라서 발생한 오류다. 대상 파일은 `music_real_voice_branch_false_positives.csv`에 기록했다.

음성 분류기는 음성 경로의 학습 파일 2,716개로만 재학습했다. 음악 경로 3,750개에는 `VOICE_FAKE` 정답이 없어, 보컬이 섞인 음악이나 분리 잔여물에서 음성 분류기의 오류를 직접 학습·검증하기 어렵다. 가짜 음성 1,330개도 모두 ASVspoof2019 LA 출처다. 이 때문에 음성 검증 EER 1.0493%를 노래·혼합음에 대한 성능으로 해석할 수 없다.

전체 1,428개에서 정답 경로를 미리 알고 해당 분기의 곱 점수만 쓰는 진단 계산은 파일 EER를 9.3838%에서 6.1625%로 낮춘다. **정답 경로를 사용한 진단이며 배포 가능한 성능이나 공식 점수 개선량이 아니다.** 실제 혼합 파일에서는 음성 분기도 필요하므로 단순히 제거해서는 안 된다. 기존 음성 head와 새 head를 같은 파일·같은 전처리에서 비교해야 이번 재학습이 오류를 늘렸는지 알 수 있다.

## 2. 출처와 길이가 정답을 대신하는 데이터 구성

음악은 FMA·Jamendo 계열이 모두 real이고 나머지 생성 데이터는 모두 fake다. train에서 출처별 fake 비율만 계산한 뒤 val에 적용하면, **오디오 없이 음악 검증 AUC 1.0 / EER 0**이다. 모델이 실제로 이 편법을 썼다는 증명은 아니지만, 현재 검증이 출처 단서를 통한 구분을 허용한다는 사실은 확인된다.

음악 학습 파일 길이의 중앙값은 real **183.9805초**, fake **10.18초**다. train의 중앙값을 보고 짧을수록 fake라는 방향을 정해 val에 적용하면, 길이만으로 AUC **0.8867446**이 나온다. 파일 길이가 입력 특성으로 직접 들어가는 것은 아니지만, 전체 길이에 따른 창 수와 구간 집계 차이가 있어 관련 영향을 별도 확인할 필요가 있다.

그룹 누수를 막고 출처·생성기 비율을 8:2로 유지한 분할은 새 출처·생성기 검증과는 다르다. 현재 val 1,428개 중 561개는 과거 실험 노출 기록이 있다. 음악 val에서는 노출 541개 중 real이 301개이고, 미노출 209개 중 real은 **1개**뿐이다. 미노출 음악 부분집합의 높은 AUC를 일반화 근거로 삼을 수 없다.

## 3. 총 파일 수 증가와 음악 학습 다양성 증가는 다르다

| 로컬 학습 구성 | Expanded | Balanced7144 |
|---|---:|---:|
| 음악 학습 파일 | 3,659 | 3,000 |
| real 음악 | 738 | 1,206 |
| fake 음악 | 2,921 | 1,794 |
| partial_fake / sham | 64 / 64 | 0 / 0 |
| 명시적 음악 구간 정답이 있는 학습 파일 | 3,659 | 597 |
| 음악 학습 파일 길이 중앙값 | 8초 | 96.8355초 |

이번 총 7,144개에는 음성 경로 3,394개가 포함된다. 음악 가짜 표본 수와 부분 조작 예제가 줄었고, 명시적인 구간 정답을 통한 보조 학습도 597개에만 가능하다. 남은 2,403개에는 파일 단위 정답만 있다. 파일별 길이도 크게 달라졌다. 따라서 7,144라는 숫자만으로 이전보다 풍부한 음악 진위 학습이라고 평가할 수 없다.

이전의 구간 정답은 준비된 데이터의 감독 정보이며 별도 수작업 검증을 의미하지 않는다. 서로 다른 split·crop·길이에 대한 지표를 그대로 전후 성능으로 비교하지 않았다. 이전 검증 예측과 현재 검증 파일의 정확한 오디오 해시 일치 항목은 0개였다.

## 4. 학습 가중치가 출처 표기의 세분화에 좌우됨

`full_bank_batches.loss_weights`는 클래스별 `(source, generator)` 칸을 동일한 비중으로 취급한다. 실제 음악 train에서는:

- `FMA/FMA` 44개: 전체 3,000개 중 1.47%이지만 파일 BCE 가중치 합의 16.67%.
- `FMA` 479개: 별도 칸으로 다시 16.67%.
- Echoes의 여러 하위 출처: 합계 30.36%.
- HAIM 전체: 3.57%.

이는 파일 BCE의 **가중치 합**이며, 실제 손실값이나 gradient 기여율 측정은 아니다. 별도 구간 손실도 포함하지 않는다. 이전 `localization_train.sampling_source`는 `/` 앞의 출처 계열로 통합하고, 클래스→출처→생성기→부모 순으로 샘플링했다. 이번 방식은 하위 경로가 많은 데이터에 더 큰 가중치를 준다. 데이터 양과 별개로 학습 분포가 달라진 원인 후보이며, 출처 이름을 정규화하고 동일 출처의 legacy/new 중복 비중을 제거하는 비교가 필요하다.

## 5. 동일한 모델 계열이어도 추론 조건은 달라짐

이전 `expanded_submission.py`는 원본 파일을 HTDemucs에 전달하고 기존 DF-Arena 분류기를 사용한다. 이번 `full_bank_submission.py`는 먼저 mono 16 kHz로 변환하고 peak가 0.6보다 크면 낮춘 후 HTDemucs에 전달한다. DF-Arena의 fc5도 3개 seed로 새로 학습했다.

고주파·스테레오 정보와 음량 처리, 음성 분류기 가중치가 동시에 바뀌었다. 영향의 크기와 방향은 아직 측정하지 않았다. 모델 이름과 큰 구조를 유지했다는 것만으로 기존 조건을 그대로 유지한 대조 실험이 되지는 않는다. 이 차이는 실험 설계에서 통제했어야 한다.

## 과적합 여부

음악 seed 41/42/43의 선택 epoch는 11/13/11이다. 이후 최종 epoch 16/18/16에서 validation BCE가 각각 0.2249→0.2427, 0.2344→0.2480, 0.2282→0.2344로 올라갔다. 후반 과적합 징후는 있지만 실제 패키지는 선택 checkpoint를 사용하므로 마지막 epoch의 악화가 그대로 제출된 것은 아니다. 음성 모델이 제한된 음성 분포에 적응했을 가능성은 별개로 확인해야 한다.

## 다음 비교의 순서

1. 직전 최고 제출 파일의 정확한 패키지를 식별해 기준선으로 고정한다. 같은 파일에서 기존 fc5와 새 fc5를 교체 비교해 음악 real 오탐 52개가 어떻게 변하는지 확인한다.
2. 같은 모델 가중치를 고정한 채 원본 입력 전처리와 mono 16 kHz·peak 제한 전처리를 비교한다. 음성 head 비교와 동시에 바꾸지 않는다.
3. 학습용 그룹 분리는 유지하되 출처·생성기를 통째로 제외한 검증과, 처음부터 접근하지 않을 평가 세트를 별도로 확보한다. 길이·음질·혼합 조건을 real/fake 간에 맞추고, 진짜 보컬 음악·배경음이 있는 음성·부분 조작 자료에 필요한 정답을 보완한다.
4. 출처 계열을 정규화한 가중치와 부분 조작/대조 예제를 복원한 조건을 각각 비교한다. 로컬 head 지표뿐 아니라 결합 후 파일 EER, 음악 real 오탐, 출처별 오류를 함께 평가한다.

지금은 ViT나 더 큰 모델보다 위 통제 비교가 우선이다. 이 분석에서는 GPU를 시작하거나 모델·학습 데이터·제출 패키지를 변경하지 않았다. 추가 데이터도 단순 총량이 아니라 부족한 음성·음악 혼합 조건과 출처별 real/fake 대조를 채우는 방향이어야 한다.
