2026-09-17 15:58:50 KST에 `wsp-9683432r72m7`의 정지를 확인했다. 현재 상태는 `stopped / standby`다. 결과 ZIP 19,192,943바이트와 579개 payload의 SHA-256 검증을 마쳤고 원래 bootstrap도 복원했다. 완료된 다운로드와 정지를 반복하지 않았다. watchdog PID 1448은 실패 처리를 마친 뒤 정상 종료한 상태이므로 재시작하지 않았다.

시작 요청부터 정지 확인까지 10분 12초였다. 이 값은 청구된 GPU 시간이나 금액의 측정값은 아니다. 원래 종료 상한 `1789631286`(16:48:06 KST)은 변경하지 않았다.

오류는 `experiment_2()`가 CPU 데이터 준비용 `v2_data`를 불러오면서 발생했다. 이 모듈은 `imageio_ffmpeg`를 import하지만 H100 환경에는 해당 패키지가 없었다. 모델 로딩이나 가중치 변환 실패가 아니다. 사전에 GPU 환경의 의존성 전체를 확인하지 못한 실행 준비 문제다.

수정한 코드는 1번에서 이미 사용한 baseline 오디오 로더를 2번에서도 재사용한다. `imageio_ffmpeg` import를 차단한 CPU 회귀 검사에서 수정 전 동일 오류를 재현했고, 수정 후 실제 준비 WAV가 그대로 디코드되고 음악·존재 확률 출력이 유지됨을 확인했다. 이 검사는 GPU encoder를 대체해 디코더 연결만 검사한다. 수정 후 H100 재실행은 하지 않았으며 기존 원격 입력 패키지와 실행 노트북은 실패 당시 증거로 보존했다.

원인을 좁힐 수 있는 결과는 얻었다. 아래 값은 dev의 REAL 음성 4개에서 측정한 DF-Arena 평균 FAKE 확률이다. 같은 4초 음성의 gain을 유지하고 반주만 바꿨다.

| 입력 | raw 경로 | vocals 경로 |
|---|---:|---:|
| 음성 단독 | 0.8% | 2.4% |
| 반주 RMS가 음성의 절반 | 16.9% | 38.5% |
| 반주 RMS가 음성과 같음 | 20.7% | 56.4% |

REAL/FAKE 음성 각 4개로 구성한 동일 dev 음성 패널에서 File EER는 단독 0%에서 두 혼합 조건 모두 25%가 됐다. 같은 음량의 혼합 조건에서 원천 라벨상 REAL 파일 4개 중 2개의 File 확률이 0.5 이상이었다. 해당 2개는 음성 성분이 File 값을 결정했고 음악 성분의 gated 확률은 각각 약 0.0134, 0.0045였다.

그러나 AI 음성 4개를 같은 음량으로 혼합했을 때 평균 FAKE 확률은 raw 47.4%, vocals 96.7%였다. 따라서 분리를 제거하거나 raw로 일괄 교체하면 AI 음성 탐지도 약해질 수 있다. 다음 검증은 동일 혼합음에서 AntiDeepfake raw/vocals를 비교하고, 실제 음성 오탐과 AI 음성 누락을 함께 확인하는 것이 우선이다. 현재 관측만으로 분리 손상과 배경 보컬 간섭을 구분할 수는 없다.

새 음악 dev 16곡의 M330 Music EER는 15초 원본 18.33%, 같은 원천의 4초 및 전화 변형은 각각 31.67%였다. 짧은 입력과 전화 음질은 추가 학습을 판단할 때 계속 회귀 조건으로 삼아야 한다. 이번 실행에서는 새 head를 학습하지 못했으므로 개선된 모델은 아직 없다.

이 수치는 공식 점수가 아니다. 음성 dev는 화자 1명, REAL/FAKE 각 4개이며 이전에 공개한 진단 패널이다. 음성 청취 검수와 가창 검증이 끝나지 않았고 음악 원천의 음성 라벨도 미확인이다. FMA/SONICS 출처 편향이 남아 있고 독립 그룹 106개로 원천 300개 기준에도 미달한다. 이번 분석에서 새 test 결과는 열지 않았다.
