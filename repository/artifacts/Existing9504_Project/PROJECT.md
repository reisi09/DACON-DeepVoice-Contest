# 프로젝트 설명

## 목적과 현재 상태

오디오 파일에서 음성·음악의 존재 여부와 각 성분의 위조 가능성을 예측하는 DACON 236749 프로젝트입니다. 출력은 `FILE_FAKE_PROB`, `VOICE_FAKE_PROB`, `MUSIC_FAKE_PROB`, `VOICE_PRESENT_PROB`, `MUSIC_PRESENT_PROB` 다섯 확률입니다.

현재 모델은 선택 데이터 9,504개를 train 6,652개, val 1,426개, test 1,426개로 나눈 Existing9504 실험의 결과입니다. H100에서 전체 선택 행의 특징 추출과 음악·음성 분류기 3개 seed 학습을 완료했고, 선택한 체크포인트 6개로 제출용 ZIP을 만들었습니다. **9,504개 전체가 학습에 사용된 것은 아닙니다. 최적화에는 train 6,652개를 사용했습니다.**

이번 패키지 제작에서는 GPU를 실행하지 않았습니다. 이 패키지는 소스·메타데이터 인수인계용이며 DACON 제출용 모델 ZIP과 다릅니다.

## 현재 모델 구조

```text
입력 오디오 → 16 kHz 로딩, 필요할 때 peak 0.6으로 제한
  ├─ PANNs → 음성 존재 확률 / 음악 존재 확률
  └─ HTDemucs base → 음성 / 반주 분리
       ├─ 음성 → DF-Arena 고정 특징 추출기 → fc5 직전 1,280차원
       │        → Linear(1280, 2) → softmax → 구간 최댓값
       │        → seed 41·42·43 평균 → 음성 위조 확률
       └─ 반주 → 약 4.04초 구간, 약 2.02초 간격, 마지막 구간 포함
                → 24 kHz 변환 → 고정 MERT330M layer 12
                → 구간 내 프레임 평균 → 1,024차원 특징
                → train 통계로 표준화 → MLP(1024 → 128 → 1, GELU)
                → 구간 logits의 log-mean-exp → sigmoid
                → seed 41·42·43 평균 → 음악 위조 확률
```

PANNs는 분리 전 오디오를 입력으로 받고, 구간별 존재 확률의 최댓값을 사용합니다. 음성 성분이 코드의 무음 기준에 해당하면 음성 위조 확률을 0으로 처리합니다.

파일 위조 확률은 `max(음성 존재 확률 × 음성 위조 확률, 음악 존재 확률 × 음악 위조 확률)`입니다. 음악 분류기의 구간 집계를 WindowMIL이라고 부릅니다. MERT 자체를 전체 미세조정하거나 ViT로 교체한 구조는 아닙니다.

| 구성 요소 | 이번 학습에서의 처리 |
|---|---|
| HTDemucs base | 고정, 음성·반주 분리 |
| MERT-v1-330M | 고정, 12번째 hidden state 특징 추출 |
| 음악 WindowMIL의 MLP | 학습 |
| DF-Arena 특징 추출기 | 고정 |
| 음성 fc5와 같은 구조의 Linear(1280, 2) | 기존 fc5 가중치로 초기화 후 학습 |
| PANNs | 고정, 성분 존재 판단 |

## 데이터와 학습 절차

검증된 후보 43,603행에서 그룹·균형 정책을 만족하는 9,504행을 선택했습니다. 총량은 약 70/15/15이며, 각 split의 real/fake 수가 같습니다. 가창은 train 전용입니다. 상세 구성과 미사용 사유는 [데이터 설명](DATASETS.md)에 있습니다.

1. 배포된 데이터 목록·오디오 해시와 환경을 검사합니다.
2. 실제 VRAM·처리량 측정으로 배치를 선택하고, HTDemucs·MERT·DF-Arena·PANNs 특징을 추출·저장합니다.
3. train의 특징만으로 정규화 통계와 학습 가중치를 구합니다.
4. 음악과 음성 분류기를 각각 seed 41, 42, 43으로 학습합니다.
5. val EER을 우선하고 같은 경우 val BCE를 비교해 체크포인트를 선택합니다.
6. 체크포인트 해시와 검증 임계값을 고정한 뒤 test를 평가합니다.
7. 모델·환경·평가 증거를 Handoff ZIP으로 보관하고 별도 제출 패키지를 만듭니다.

옵티마이저는 AdamW, 학습률은 음악 `1e-3`, 음성 `1e-4`, weight decay는 `0.01`입니다. 최대 50 epoch, 개선이 없는 5 epoch에서 조기 종료하며 유효 학습 배치는 256입니다. 모델·옵티마이저·난수 상태를 저장해 epoch 경계에서 재개합니다.

H100의 MERT 특징 추출 배치 측정에서는 256개 구간이 선택됐습니다. 해당 측정의 peak allocated memory는 26,930,737,664바이트였습니다. 이는 측정 지점의 CUDA 할당량이며 전체 작업의 최대 VRAM이나 모든 파일의 처리량을 보증하지 않습니다. 최종 제출 추론은 기본 구간 배치 8을 사용합니다. 특징 추출 배치와 학습·제출 배치를 구분해야 합니다.

## 확인된 결과

| 지표 | val | test |
|---|---:|---:|
| 파일 EER | 7.9944% | 7.4334% |
| 음악 EER | 9.1176% | 9.0909% |
| 음성 EER | 0.8043% | 0.0000% |

정확한 값과 평가 대상 수는 `evidence/metrics/val_metrics.json`, `test_metrics.json`에 있습니다. 성분별 지표는 해당 라벨을 아는 행만 평가하므로 분모가 서로 다릅니다. 이 수치는 **로컬 평가 결과이며 공식 리더보드 점수가 아닙니다.**

완료 Handoff의 모든 136개 항목을 SHA-256·CRC로 검증했고, 특징 목록 9,504행과 체크포인트 6개의 해시를 확인했습니다. 제출 ZIP의 실제 추론 코드는 네트워크 연결을 차단한 macOS CPU에서 별도 검증했습니다. 일반 원본 7개의 H100 기준 예측 대비 최대 절대 오차는 `0.0007349252700805664`로, 사전 지정한 허용 오차 `0.002` 이내였습니다. 순서를 바꾼 2개 파일의 결과 차이는 0이었습니다. 기존 음량을 보존해야 하는 3개 원본은 별도로 검사했고 최대 절대 오차는 `0.0003068248430887488`이었습니다.

## 해석의 한계

- val 997개, test 1,001개는 과거 개발 과정의 노출 그룹입니다. 이번 실행에서 test를 체크포인트 선택 후 평가했어도 독립 테스트라고 부를 수 없습니다.
- 가창 2,034개는 train에만 있습니다. 가창과 일부 소수 생성기의 val/test 성능은 측정하지 못했습니다.
- 음악의 출처·길이 편향이 남았습니다. 데이터 구성 진단에서 출처만 사용한 음악 AUC는 val 약 0.9665, test 약 0.9686이었습니다. 이는 모델 성능이 아니라 출처 정보로 라벨을 구별할 여지가 크다는 진단입니다.
- unknown 성분 라벨은 마스크로 제외합니다. 모르는 라벨을 real로 간주하지 않습니다.
- Linux/CUDA/L4에서 최종 제출 ZIP 전체의 실행시간과 호환성은 검증하지 않았습니다. CPU 추론 일치 검증이 이 조건을 대신하지 않습니다.
- H100 작업은 중단 후 캐시를 재사용한 이력이 있어 마지막 재개 구간의 시간만으로 총 학습시간이나 비용을 계산하면 안 됩니다.

모델 구조·분할·파라미터를 이번 문서화 과정에서 변경하지 않았습니다. 새 학습이나 DACON 제출도 수행하지 않았습니다.
