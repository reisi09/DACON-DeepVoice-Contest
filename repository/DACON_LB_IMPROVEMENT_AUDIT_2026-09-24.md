# DACON 236749 리더보드 개선 감사 보고서

작성일: 2026-09-24. Claude Code의 `dacon-lb-improvement-audit`를 이어받아 작성했다. 범위는 기존 기록·데이터·코드의 분석과 개선안이며, 학습·추론 코드 수정, GPU 기동, 데이터 수집, 대회 제출은 수행하지 않았다.

## 1. 핵심 결론

1. **우선 해결할 대상은 음악과 가창이 포함된 파일이다.** 현재 프록시의 FILE 오류 705건 중 538건이 음악 포함 파일에서 발생한다. 음악 헤드와 노래 속 보컬 판별을 함께 개선해야 한다. 숨은 테스트에서도 같은 비중인지는 알 수 없다.
2. **새 백본을 추가하기 전에 데이터 구성과 검증 기준부터 바로잡는다.** Echoes 생성기 파싱 오류, 구성물의 split 쏠림, 혼합 진위·가창 표본 공백은 확인하거나 점검할 구체적인 대상이다.
3. **현재 0.8767과 리더보드 0.7913을 동등한 평가값으로 비교하면 안 된다.** 전자는 일부 라벨을 제외한 참고 합산치이고, 후자는 사용자가 제공한 공식 제출 화면의 기록이다. 오류 원인을 하나의 배율이나 길이 효과로 설명할 근거도 없다.
4. **실행 순서는 데이터·분할 정리 → 기존 특징으로 작은 비교 → 권리 확인을 통과한 표적 데이터 보강 → 필요할 때만 표현 학습 변경이다.** Presence 모델 교체와 대형 백본 일괄 추가는 뒤로 미룬다.
5. **점수 상승 폭은 아직 측정되지 않았다.** 아래 비용·표본 수·일정은 실행 계획이다. 기존 모델, 기존 제출물과 원본 데이터는 보존한다.

## 2. 문제점 정밀 진단

### 2.1 구조와 추론

현재 경로는 `16 kHz mono → HTDemucs → 보컬/반주 stem`이다. 보컬은 동결 DF-Arena 특징과 fc5 선형 헤드, 반주는 동결 MERT L12 특징과 WindowMIL 헤드를 거친다. 음성은 세그먼트 최댓값, 음악은 log-mean-exp를 사용하며, 3개 seed의 결과를 평균한다. PANNs 기반 presence와 검증셋에서 적합한 CDF 결합층이 FILE 점수를 만든다. 근거: `full_bank_submission.py:73`, `full_bank_train.py:76`, `decision_heads.py` 및 패키지 README. 현재 작업 트리에 수정이 있으므로 제출 당시 동작과 비교할 때는 패키지에 포함된 소스를 기준으로 해야 한다.

### 2.2 데이터 구성과 split

**Echoes 생성기 파싱은 먼저 바로잡을 문제다.** `data_v4/build_manifest.py:135`는 `TTA/ATA` 앞의 디렉터리를 생성기로 읽는다. 실제 manifest의 ID에는 `Echoes/TTA/musicgen/...`, `Echoes/TTA/brev/...`가 있는데 두 행 모두 `generator=Echoes/TTA`다. 이번 전수 집계에서도 신규 Echoes 594행이 `Echoes/TTA` 300행과 `Echoes/ATA` 294행으로만 나뉘었다. 생성기별 cap과 학습 가중이 이 잘못된 메타데이터를 사용한다.

추후 수정 시에는 파서 한 줄만 고치고 끝내면 안 된다. 실제 디렉터리의 생성기 이름을 복원하고, 원곡·참조곡 단위 group을 유지하며, 전장 자료와 레거시 8초 crop의 중복·별칭을 합쳐야 한다. 그다음 cap과 가중을 다시 계산한다. 기존 검증은 레거시 fake 음악 582행이 duration-balance 이후 음악 fake 가중의 약 41.4%를 차지했다고 보고했다. 재선택으로 정확히 몇 행을 더 확보할 수 있는지는 새 manifest를 만들기 전까지 추정치다. **이번 감사에서는 코드를 고치지 않았다.**

**구성물을 만든 뒤 component closure를 적용하면서 특정 실제 범주가 test로 쏠렸다.** 기존 반박 검증에서는 구성 song 400행이 모두 test로 이동했고, 실제 BGM 혼합·향상 음성도 train에 적게 남았다. 이는 원천 누수를 막기 위한 연결 보존 자체가 잘못됐다는 뜻은 아니다. 부모 원천의 split을 먼저 고정하고 **같은 split 안에서만 구성물**을 만들어야 한다. 연결을 끊어 부모와 자식을 다른 split에 두는 방식은 사용하지 않는다.

bank는 train **30,658행**, val **4,931행**, test **6,450행**이다. train에 사용하지 않은 val/test를 모두 넣으면 데이터는 늘지만 평가도 함께 사라진다. 최종 refit을 하더라도 레시피·epoch·가중을 먼저 동결하고, 별도로 잠근 원천 holdout을 남겨야 한다. 한번 학습에 넣은 기존 test의 수치를 이후 일반화 성능으로 다시 인용하지 않는다.

refit 뒤 FILE 결합은 검증된 기존 매개변수를 고정하거나, upstream 헤드가 학습하지 않은 별도 calibration 표본으로 다시 적합한다. group OOF를 택한다면 upstream 헤드의 예측부터 누수 없이 생성해야 한다. 헤드가 이미 본 행의 예측을 놓고 결합층만 fold로 나누는 것은 누수 없는 OOF가 아니다. 최종 holdout은 calibration에도 쓰지 않는다.

### 2.3 데이터셋과 라벨

- **혼합 진위와 가창 공백:** 기존 검증에서 fake a cappella와 AI 변환 가창의 부족이 확인됐다. 보컬·반주가 모두 fake인 노래를 늘리는 것만으로는 `real 보컬+AI 반주`, `AI 보컬+real 반주`를 학습할 수 없다. 네 조합을 각각 확보한다.
- **표본 가중의 왜곡:** `(label, source, generator)` 셀 균등 가중은 작은 셀과 중복 별칭의 비중을 키운다. 별칭·생성기 표기를 정규화한 뒤 실효 표본 수와 가창/발화별 가중을 확인한다. 한국어 비중이 작다는 이유만으로 가중을 올리지는 않는다. 현재 한국어 프록시가 오히려 쉬운 편이라는 반대 근거가 있다.
- **원천과 라벨의 결합:** 특정 실제 코퍼스와 특정 fake 코퍼스를 구분해도 높은 점수를 얻는 구조다. 원천별 fake 비율만 쓴 음성 전용 진단의 높은 AUC는 경고 신호다. 그 수치를 실제 모델이 원천 정보만 쓴다는 인과 증거로 해석하지 않는다.
- **길고 자연스러운 발화의 검증 공백:** test의 voice-only는 real 최대 26.58초, fake 최대 24.803초로 30초 이상 구간을 대표하지 못한다. 반면 train에는 30초 이상 fake voice-only가 4행 있다. “학습에는 긴 음성이 전혀 없다”는 기존 단정은 틀렸다. 길이·발화/가창·원천을 교차해서 집계한다.
- **메타데이터 결측:** train/val의 실제 음악 4,441행은 언어가 모두 미기재다. 이 자료만으로 한국어 음악이 없다고 결론낼 수 없다. 곡의 상업적 제작 수준도 별도 검토 없이 코퍼스 이름만으로 단정하지 않는다.
- **불명확한 성분 라벨:** 가사 존재나 separator의 보컬 검출 실패만으로 `VOICE_PRESENT=0` 또는 `VOICE_FAKE=1`을 확정하지 않는다. 모호한 라벨은 마스크로 관리하되 제외한 범위와 분모를 보고한다. 생성형 mastering/style transfer도 대회의 생성·비생성 편집 구분에 맞춰 별도로 점검한다.
- **전처리 단서:** 원본 코덱·sample rate·채널·길이·음량이 라벨이나 코퍼스와 함께 변할 수 있다. 재인코딩 조건을 맞추는 것만으로 원본 생성·압축 흔적까지 없어지는 것은 아니다. 자연 발생 전화 전송과 모의 코덱도 구분한다.

### 2.4 검증과 실험 이력

기존의 “프록시 개선 +0.059가 LB에서는 +0.033으로 줄었다”는 문장은 비교 기준 패키지를 확인해야 한다. `Existing9504`, `Balanced7144`, 기록상 최고 제출이 항상 동일한 모델이라는 증거는 부족하다. 과거 로컬 평가와 전체 재학습 ZIP도 구분해야 한다. **서로 다른 모델·패널의 차이로 하나의 전이율을 만들지 않는다.**

길이 균등 재가중은 시나리오 분석일 뿐이다. 숨은 테스트 길이 분포는 공개되지 않았고, 긴 구간에는 Lyria·MUSAN 같은 어려운 원천이 집중된다. “길이가 LB 격차의 40%를 설명한다”, “항상 1.69배로 보정하면 된다”는 주장은 채택하지 않는다. 과거 실패한 backbone/fullFT 실험도 당시 데이터·검증·패키지 조건에서의 결과이지 방법 전체의 실패 증명이 아니다.

### 2.5 운영과 패키지

Presence의 CPS가 기록상 0.9976771958이므로, ADS가 그대로일 때 CPS만 1로 올려 얻을 수 있는 총점 증가는 최대 **0.00023228042**다. Presence 모델 교체를 우선할 이유가 약하다. 단, presence가 FILE 결합 입력으로 들어가므로 FILE에 미치는 간접 효과까지 이 상한으로 제한할 수는 없다.

제출 화면의 17분 32초는 해당 제출의 실제 기록이다. 이후 다른 백본·더 많은 window·정밀도 변경을 적용한 패키지가 같은 시간에 돈다는 증거는 아니다. H100·CPU 결과로 L4 소요 시간이나 메모리를 확정하지 않는다. 기존 runtime 추정에는 모델 호출 횟수와 저장 배열의 요약값을 window로 잘못 센 문제가 있어, 세부 분 단위 추정은 의사결정 근거에서 제외한다.

구체적으로 AntiDeepfake 저장 배열은 `[max, top30_mean, *window_probs]` 형식이다. 4,020개 저장값에서 728번 호출의 요약값 두 개씩을 빼면 실제 window는 **2,564개**다. 이 구간의 93.12초에는 IO와 결합 처리도 포함되므로 순수 GPU 처리량으로 해석하지 않는다. 기존 균형 학습도 18개 헤드가 아니라 **2개 경로×3개 seed=6개 헤드**이며 기록된 학습 단계는 **455초**다. 음성 seed 두 개가 50 epoch에 도달했다는 사실만으로 미학습을 확정할 수 없다.

## 3. 개선안 우선순위

아래 시간은 실행 계획의 예산이며 실제 완료 시간이나 성능 보장이 아니다. 리더보드 이득은 모두 **미측정**이다.

| 순서 | 할 일 | 기대하는 변화·판단 기준 | 비용·위험·의존성 | 특징 재추출 |
|---|---|---|---|---|
| P0-1 | 기준 ZIP·예측·split·원천 revision을 묶어 고정 | 패키지 불일치와 분모 혼동을 없앤다 | CPU 문서·해시 작업. 현재 학습 코드의 기존 수정과 분리 | 없음 |
| P0-2 | Echoes 생성기/별칭·중복 정리, split 안에서 구성물 생성 | 잘못된 cap·가중과 train의 범주 공백을 줄인다 | 기존 레거시와 합쳐 가중을 다시 계산해야 함 | 기존 행은 조건부 재사용, 새 crop은 필요 |
| P0-3 | 원천 holdout·긴 발화·혼합 진위 평가셋을 동결 | 값싼 개선이 쉬운 코퍼스만 좋아지는지 가린다 | 권리와 component 분리 확인. 기존 test 재활용 한계 표기 | 새 평가 오디오만 필요 |
| P1-1 | 기존 특징으로 가창/발화 가중 및 공동 특징 헤드 비교 | 가창 보컬·실제 음악 오류 감소, 혼합 진위 퇴행 없음 | 캐시 접근·시간 정렬·학습 레시피 고정 필요. 먼저 1 seed, 채택 후보만 3 seeds | 이미 필요한 특징이 있을 때 없음 |
| P1-2 | 실제 음악·최신 생성 음악·가창·혼합 진위의 작은 보강 | 소스 내부와 미관측 소스 양쪽에서 개선 | 아래 4,400행 파일럿. 라이선스와 수율 통과 후 진행 | 추가 행만 |
| P2-1 | max/LME/top-k를 학습과 추론에 같은 방식으로 비교 | 긴 real FP를 줄이되 부분 fake FN을 늘리지 않음 | 긴 발화·부분 fake 평가가 먼저. overlap은 별개 변수 | 기존 세그먼트 pooling만 바꾸면 없음 |
| P2-2 | raw+stem 또는 다층 MERT의 제한된 비교 | 실제 음악·가창 분리가 재현성 있게 개선 | 원천·길이 통제, ZIP/L4 검증. raw 분기의 성분 간 오탐 위험 | 필요 |
| P3 | AntiDeepfake 등 두 번째 백본, 부분 fine-tuning | 앞 단계로 설명되지 않는 표현 한계 해결 | 외부 checkpoint·라이선스·실행시간 확인 후 단일 후보만 | 필요 |

수집·head 재적합보다 대형 모델 교체를 먼저 하지 않는다. 반대로 메타데이터 오류를 고치는 것만으로 점수가 오를 것이라고 단정하지도 않는다. 새 후보는 동일한 데이터·같은 inference 경로의 기준 모델과 비교하고, 성분별 변화와 FILE 결합 결과를 함께 기록한다.

전처리는 라벨별로 같은 길이 구간을 적용하고 원본 파일·원본 코덱·채널을 보존한다. 4초보다 짧은 자료를 단순 반복해 긴 평가 오디오의 대용으로 삼지 않는다. 긴 발화 연결은 자연 발생 긴 발화와 별도 범주로 기록한다. separator의 보컬 비율은 보조 근거이며 라벨 정답으로 취급하지 않는다.

생성 파일은 모델 revision·seed·prompt·매개변수·입력 원본·권리 근거를 묶는다. 실제 학습 파일과 재현 코드를 제출할 수 있어야 한다. 원본 아카이브는 URL이 있다는 이유로 삭제하지 않는다. 근거: [공식 규칙](https://dacon.io/competitions/official/236749/overview/rules), [학습 파일·증강 제출 답변](https://dacon.io/competitions/official/236749/talkboard/417280).

### 4.3 비용은 작은 표본으로 다시 산정

기존 H100 작업에서 약 110.38 audio-hour를 처리한 특징 단계의 경과 시간은 5시간 44분 4초였다. 처리량은 약 **19.25 audio-hour/단계 경과 시간 1시간**이다. 이 단계에는 일반적인 HTDemucs 분리, 특징 추출, presence 처리와 캐시 쓰기가 포함된다. 같은 처리량을 가정하면 4,400행×평균 22초는 약 26.9 audio-hour이며, 해당 단계에 약 **1.40시간**이 필요하다. **이는 외삽값**이다. 생성·다운로드·새 혼합물을 만들기 위한 추가 분리·materialization·재시도 등 기록된 단계 밖의 작업은 별도다. 먼저 실제 파일럿 200–500개로 단계별 처리량과 수율을 측정한다.

기존 수집안의 항목을 중복 없이 더하면 15–16k가 아니라 **20,200행**이었다. 같은 가정으로 위 특징 단계에 약 6.4시간이 걸리고 생성 등 외부 단계도 더해야 한다. 이 안을 그대로 실행하지 않는다. 새 유료 자원을 만들거나 과거 승인 한도를 이번 실행 허가로 간주하지 않는다. 실행을 결정할 때 기존 workspace와 저장소 여유를 먼저 확인하고, 생성·추출 각각의 종료 시각과 누적 GPU 예산을 고정한다.

## 5. 구조 개선 설계

**1단계: 현재 backbone과 presence를 유지한다.** 메타데이터·split·가중을 정리하고 같은 모델에서 데이터 효과를 먼저 측정한다. 비교를 위해 기존 FILE CDF 표와 결합 가중을 고정한 결과를 먼저 낸다. 헤드 점수 분포가 바뀐 후보는 별도의 calibration 예측으로 같은 결합 방법을 다시 적합한 결과도 구분해 보고한다. 최종 holdout으로 CDF나 가중을 맞추지 않는다. 실제 음성과 가창을 단순히 서로 다른 라벨로 구분하게 만드는 방식은 피한다.

**2단계: 보컬·반주 특징을 함께 쓰는 작은 헤드를 제한적으로 비교한다.** 캐시의 MERT window와 DF-Arena 특징을 시간 정렬하거나 파일 단위로 집계해 사용한다. `MUSIC_FAKE`, `VOICE_FAKE`, `FILE_FAKE`의 정답은 각각 유지한다. 음악 점수를 보컬의 정답처럼 복사하지 않는다. `real 보컬+AI 반주`에서 보컬 FP가 늘고 `AI 보컬+real 반주`에서 FN이 늘면 채택하지 않는다. [CLAM](https://arxiv.org/html/2512.00621) 같은 외부 연구는 다중 표현의 가능성을 뒷받침하지만, 논문 전체 모델의 수치를 단순 캐시 결합의 성능으로 인용하지 않는다.

**3단계: 필요한 변화만 새 특징을 추출한다.** raw+stem 또는 MERT 다층을 하나씩 비교한다. full-mix 음악 검출은 가짜 음성이 실제 반주의 Music 점수로 새어 들어갈 수 있으므로 혼합 진위 평가가 필수다. MERT의 불필요한 후반층 제거, 파일 내부 segment batching, 낮은 정밀도는 정확도 개선과 별도의 런타임 최적화 실험으로 다룬다. `hidden_states[12]`의 위치와 마지막 layer norm 동작을 확인하지 않고 단순히 층 수를 12로 자르지 않는다.

**4단계: 새 backbone은 한 후보만 추가한다.** [AntiDeepfake](https://huggingface.co/nii-yamagishilab/xls-r-1b-anti-deepfake) 등은 실제 다운로드할 checkpoint·학습 자료·라이선스·입력 범위를 확인한 뒤 별도 후보로 둔다. 외부 벤치마크에서 fine-tuning한 결과를 zero-shot checkpoint 성능으로 옮기지 않는다. speech용 detector가 가창에도 유효하다는 가정은 별도 검증한다.

L4 60분·ZIP 10GB 조건 안의 채택 기준은 새 패키지의 실제 실행이다. 계획상 45분 이내를 목표로 15분 여유를 둘 수 있지만, 이는 측정값이 아니다. 현재 ZIP의 수치상 여유는 약 3.65GB이며, 압축률과 중복 자산 때문에 추가 가중치 크기만으로 최종 용량을 확정하지 않는다. 근거: [공식 평가 환경](https://dacon.io/competitions/official/236749/overview/evaluation).

## 6. 검증 체계 재설계와 제출 계획

### 6.1 세 층으로 평가

1. **개발 val:** 가중·pooling·헤드 후보를 선택한다. 원천 component 단위로 분리하고 모든 후보에 같은 mask와 분모를 사용한다.
2. **잠근 원천 holdout:** 새로운 코퍼스·생성기·가수/화자·원곡이 학습과 겹치지 않게 한다. 4–60초, 긴 발화, 보컬 유무, 혼합 진위, 전화채널을 따로 보고한다. 한 클래스만 있는 셀에서 EER을 만들지 않고 FPR/FNR과 분모를 적는다.
3. **실제 제출 패키지:** 원래 오디오에서 마지막 CSV까지 실행한다. 기준과 후보의 입력·ZIP 해시를 묶고, 파일 순서를 바꾸거나 subset으로 실행해 다른 파일의 정보가 섞이지 않는지 확인한다. 로컬 확인과 L4 확인을 구분한다.

차이는 같은 파일의 paired 비교와 component 단위 bootstrap으로 본다. 전체 평균 개선과 주요 슬라이스 퇴행을 함께 보고, 여러 실험을 본 test를 계속 미사용 holdout으로 부르지 않는다. 모델이 아니라 쉬운 코퍼스를 골라내는 검증셋 조정을 피한다.

### 6.2 하루 최대 3회 제출은 단일 변화 비교에 배정

권장 순서는 **음악 데이터/헤드만 바꾼 후보 → 가창·혼합 진위 후보 → 채택 조합**이다. 매번 나머지 출력과 코드가 무엇을 유지했는지 기록한다. 전날보다 새 근거가 없으면 슬롯을 채우기 위해 무의미한 후보를 만들지 않는다. 남은 실제 제출 횟수는 계정에서 확인해야 하며 이 감사에서는 확인하지 않았다.

ADS에서 성분을 분해하는 진단 제출도 선택지다. 기준 ADS를 `A0`, 한 성분의 출력만 상수 0.5로 바꾼 ADS를 `Ac`, 해당 가중을 `w`라 하면 두 클래스가 존재하고 공식 이산 EER 규칙을 사용할 때 `E_component = 0.5 + (Ac - A0)/w`다. `w`는 FILE 0.5, VOICE 0.2, MUSIC 0.3이다. 나머지 출력, 특히 FILE 결합값과 presence를 **정확히 고정**해야 하며, 10자리 ADS를 사용한다. 의미 있는 모델 비교 슬롯을 소모하므로 실제 의사결정을 바꿀 때만 쓴다.

Public과 최종 점수 관계가 같더라도 반복 제출에 따른 선택 편향이 사라지는 것은 아니다. 이 방법으로 개별 숨은 파일의 라벨을 추정하거나 숨은 데이터로 학습·튜닝·pseudo-labeling을 하지 않는다. 파일 간 통계 보정도 금지된다. 근거: [공식 규칙](https://dacon.io/competitions/official/236749/overview/rules), [평가 안내](https://dacon.io/competitions/official/236749/overview/evaluation).

### 이번에 수행한 검증

- Claude workflow의 8개 분석 결과 **87건**과 기존 반박 검증 **21건**을 복구했다. 원본 journal의 SHA-256과 각 항목의 출처를 보존했다.
- 기존에 끝나지 않았거나 시작되지 않은 critical/high **16건**은 이번 작업에서 별도로 검토했다. 원래 모델의 동의를 검증 근거로 삼지 않고, 실제 CSV·manifest·로그·소스·공식 웹 문서를 대조했다.
- 핵심 지표를 실제 예측 CSV에서 다시 계산하고 분모·마스크·부분 점수 경계를 확인했다. 음악 포함 파일의 오류 기여와 Echoes 생성기 수, train/val 행 수도 독립 집계했다.
- 외부 모델과 데이터의 공개 조건, 라이선스 충돌, 논문 수치의 적용 범위, 대회 일정·규칙을 확인했다. 파일별 원저작권이나 모든 후보 데이터의 적합성을 보증한 것은 아니다.
- 학습·신규 모델 추론·데이터 다운로드·L4 실행·공식 제출은 수행하지 않았다. 과거에 실행된 결과와 이번에 다시 계산한 값을 증거 파일에서 구분했다.

중간 이하 중요도 50건은 원래 분석의 후보·근거를 보존하되 전부 독립 재실행한 것으로 표시하지 않는다. 각 항목의 수정된 주장과 남은 한계는 [전체 항목 장부](.omo/evidence/dacon-lb-improvement-audit-20260924/findings_ledger.json), 새 검증과 측정은 [감사 증거](.omo/evidence/dacon-lb-improvement-audit-20260924/audit_receipt.json)에 있다.

GPT-6 Pro Chat 위임은 제출하지 않았다. 일반 Chat 화면과 `최신 / Pro` 최고 설정은 확인했으나 명시적인 `GPT-6 Pro` 모델명을 확인하지 못했다. 따라서 GPT-6 Pro가 작성·검토했다고 표시하지 않는다. 수동 위임용 자료는 [준비된 요청](.omo/evidence/dacon-lb-improvement-audit-20260924/chat_handoff.md)에 남긴다. 이번 최종 보고서는 복구한 분석을 통합하고 위의 근거 검증을 반영한 결과다.
